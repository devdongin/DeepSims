# 리뷰 평가표 (필수 산출물)

가상 플레이어·QA 엔지니어 등 **모든 리뷰어는 서술과 함께 아래 표를 반드시 채운다.**
서술만 있으면 회차 간 비교가 안 되고 "좋아졌나?"에 답할 수 없다. 점수는 회차마다
같은 기준으로 매겨져야 추세가 의미를 갖는다.

## 1. 항목별 점수 (각 10점 만점)

| 항목 | 무엇을 보는가 | 1점 | 10점 |
|---|---|---|---|
| **재미** | 다음에 무슨 일이 벌어질지 궁금해서 계속 보게 되는가 | 3분 만에 닫고 싶다 | 시간 가는 줄 몰랐다 |
| **버그·안정성** | 의도대로 동작하는가, 깨지면 알려주는가 | 간판 기능이 조용히 죽어 있다 | 부수려 해도 안 부서진다 |
| **이해도(온보딩)** | 내가 누구고 뭘 해야 하는지 알겠는가 | 역할도 목표도 모르겠다 | 설명 없이도 바로 안다 |
| **조작·UI** | 하고 싶은 걸 할 수 있는가, 반응이 오는가 | 눌러도 아무 반응이 없다 | 원하는 게 항상 손에 닿는다 |
| **세계의 그럴듯함** | 사람들의 행동과 경제가 납득되는가 | 이유 없이 굶고 이유 없이 부자다 | 왜 그랬는지 설명이 된다 |
| **보는 재미(그래픽·연출)** | 화면이 볼 만한가 | 목업 같다 | 계속 구경하게 된다 |
| **성능** | 끊김·발열·메모리 | 몇 분 만에 느려진다 | 오래 켜둬도 그대로다 |
| **문서·첫 설치** | README대로 하면 되는가 | 세 줄 만에 막힌다 | 막힘 없이 5분 안에 플레이 |

각 점수 옆에 **한 줄 근거**를 반드시 적는다. 근거 없는 점수는 무효다.

## 2. 총 별점 (★ 5점 만점, 0.5 단위)

**항목 평균의 반올림이 아니다.** "이 게임을 지금 남에게 추천하겠는가"에 대한
리뷰어의 종합 판단이며, 평균과 다르면 왜 다른지 한 줄로 설명한다.
(예: 항목 평균은 6.4지만 간판 기능이 죽어 있어 ★2.5 — 추천할 수 없다.)

| 별점 | 뜻 |
|---|---|
| ★5.0 | 지금 사서 해도 아깝지 않다 |
| ★4.0 | 친구에게 권하겠다 |
| ★3.0 | 취향 맞으면 권하겠다 |
| ★2.0 | 아직은 못 권한다 |
| ★1.0 | 켜지 마라 |

## 3. 함께 내는 항목

- **계속 하겠는가**: 예/아니오 + **한 문장 이유** (예라면 "게임으로서"인지 "관찰
  대상으로서"인지 명시 — 이 둘은 전혀 다른 신호다)
- **가장 좋았던 것 하나 / 가장 실망한 것 하나**
- **바라는 것 3개** (우선순위 순)

## 4. 출력 형식 (그대로 복사해서 채운다)

```
## 점수

| 항목 | 점수 | 근거 |
|---|---|---|
| 재미 | ?/10 | |
| 버그·안정성 | ?/10 | |
| 이해도(온보딩) | ?/10 | |
| 조작·UI | ?/10 | |
| 세계의 그럴듯함 | ?/10 | |
| 보는 재미 | ?/10 | |
| 성능 | ?/10 | |
| 문서·첫 설치 | ?/10 | |
| **항목 평균** | **?.?/10** | |

**총 별점: ★?.? / 5.0**
(평균과 다르다면 이유: )

**계속 하겠는가**: 예/아니오 — 이유
```

## 5. 채점 규칙

- **후하게 주지 마라.** 7점은 "잘 만들었다"이지 "괜찮다"가 아니다. 기본값은 5점이고,
  거기서 올리거나 내릴 **관측된 근거**가 있어야 움직인다.
- **못 본 것에는 점수를 주지 마라.** 검수하지 못한 항목은 점수 대신 `미검증`이라 쓰고
  커버리지 노트에 왜 못 봤는지 적는다. 추측으로 채운 점수가 제일 해롭다.
- **같은 결함을 여러 항목에서 중복 감점하지 마라.** 배속 버그는 '버그·안정성'에서
  깎고, '재미'에서는 그 버그를 만나기 전까지의 경험으로 매긴다.
- 점수는 **이 게임이 되려는 것**(결정적 심즈라이크 + 도시 타이쿤) 기준이다. 다른
  장르였으면 좋았겠다는 감점은 하지 않는다.
