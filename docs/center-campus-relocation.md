# 사용자 중심시 개발 불능 재현과 수정

현재 플레이 파일과 원래 제보 세계는 다르다. 읽기 전용 조사에서 현재 root/deepsims.db는
16:40:43에 생성된 seed556869242이고 중심시 입력이 없다. archive1113 보관본은
seed20260831, tick3667916이며 center0(186,120)와 적용된 plan_center 입력2793782,
university0(186,80)8×6를 보존한다. 보관본/플레이 파일을 쓰거나 서버를 재시작하지 않았다.

원래 세계를 메모리에 이관하면 plot73(186,120)은 여전히 건축 불가다. 도로x192와
도로y115, 인도y125 사이에 있는 필지인데, 기존 복구는 보호용 대학12×10을 찾으면서
L1 탐색 반경8만 허용했다. 최소의 유효 이동은(180,126), 거리12이므로 찾을 수 없었다.
기존 회귀는 수직 도로만 재현하여(180,120) 거리6 이동에 통과했고 교차 인도를 놓쳤다.

logic109는 보호 footprint의 폭+높이를 탐색 상한으로 쓰고, 후보도 동일 관할 중심시
영향권에 남도록 검사한다. 타일을 지우지 않으며 기존 건물/필지/예약 보호는 유지한다.
실제 보관본 메모리 복사와 최소 세 지형 띠 회귀에서(180,126)으로 이동하고12×10 판정이
성공하며 전체 타일 배열이 불변인 것을 확인했다. 제보자가 플레이 중인 파일에 중심시를
임의로 추가하거나 옛 세계를 복구한 것은 아니다. 복구는 현재 진행을 바꾸므로 별도 결정이다.

`node bench/center-archive-audit.js <보관본 경로>`는 DB를 readonly로 읽고 닫은 뒤
메모리에서만 다음 계획일까지 전진한다. 실제 보관본의3667916→3669121 검증에서
tick3669120에 primary_school이 plot73에서 자동 착공했다. 입력/욕구/돈/인구를 주입하지
않았으며 착공과 완공을 혼동하지 않는다. 현재 라이브 파일은 이 감사에 쓰지 않았다.

중심시는 건물 생성 명령이 아니라 배치 유도다. 수정은 usable parcel 병목을 해소하며
실제 착공은 기존 수요/재정/노동 규칙을 따른다. 대학은 신규12×10, 기존8×6 자동 확대 없음.
