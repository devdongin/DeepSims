# #48 교통 계측 검증

관측 전용 schema61, 로직 v57 유지. `transportStats.today`는 진행 중인 날,
`history`는 완료된 최근 14일이다. `statsHistory[].transport`는 전날 요약이며 중첩된
`day`가 실제 계측 날짜다. OD는 목적·32칸 격자 출발/도착·차량 여부 키로 집계한다.
차량 여부는 기존 이동 규칙의 `hasCar`와 같은 뜻이며, 도로·주차 선택을 새로 만들지 않는다.

`walkingTicks`는 그 날 실제 전진에 사용한 tick 수다(차량의 여러 칸 전진도 tick당 1).
`completedWalkingTicks`는 그 날 도착한 전체 관측 여정의 소요 tick 합이다. 자정을 넘는
여정은 두 값의 집계 구간이 다르다. 구 세이브의 출발 미관측 여정은 `partialArrivals`로
구분하며 평균 완료 시간에 섞지 않는다. 경로 길이 0인 행동 시작도 출발 수와 별도다.

## 기준 구현과 3일 비교

seed4800으로 직전 병합 구현 e86bec5와 계측 구현을 4,320 tick 나란히 실행했다.
매 tick 전체 이벤트가 동일했고, 신규 관측 필드와 schema 번호만 제거한 최종 세계 해시는
양쪽 모두 `5136a23e`였다. 후보/선택/이벤트/세계 기준 오라클도 기존 벡터를 그대로 유지한다.

전날 출발한 사람이 다음 날 도착할 수 있으므로 일별 출발과 도착이 같을 필요는 없다.
이 시드의 3일에는 차량 출발이 0이었다. 차량 2칸/1tick은 독립 회귀로 검증한다.
혼잡·주차·유발 수요 모델은 없으므로 그 피해가 0이라고 해석하지 않는다.

회귀는 목적·OD·정수 산식, 차량 이동 시간, 자정 도착, 취소, 부분 관측, 경로0,
도로 이벤트, 14일 상한, v60 이관, 이동 중 저장 후 재생 동일성을 다룬다.

전체 회귀 405/405와 빌드가 통과했다. 계측 정리의 반복 비용을 줄인 뒤 집중 회귀
22/22도 통과했다. 인구200, 워밍업200tick 뒤 2,000tick을 3회 교대 실행한 시간(ms)은
기준 `[3613,3145,4370]`, 계측 `[3591,3050,4422]`였다. 실행 환경 편차가 커 속도 개선으로
주장하지 않으며, 이 표본에서 지속적인 성능 저하 신호는 없었다.
