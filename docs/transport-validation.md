## #32 역 건설 검증 (logic81/schema72)

`node bench/station-construction.js 32`는 시드 월드의 지형·인구·직업·욕구·돈·수요를
바꾸지 않는다. 실제 수요 해금 뒤 재원이 있는 건설 가능 공터에 시장 건설 명령 하나만
넣는다. 강제 노동·순간 완공·짧은 공사량을 사용하지 않는다.

seed32 결과: 17일차 수요 해금, tick24481 공터0(50,4)에8000원 지출 후 국고2675,
같은 tick에 required18000(정상20000×시장90%) 착공, tick29502 역 완공, 인구16.
전체 관측 기간 건설 행동 시작1005회이며 **역 공사만의 시작 횟수는 아니다**.
부적격 노동0, no_path0, 매 tick 닫힌 회계17063 유지. `--resume`은 실제 역 프로젝트의
진척이 절반에 도달했을 때 저장·복원하며 연속 실행과 출력 JSON 전체가 일치한다
(hash fd25034f). 자연 수요 해금→시장 명령→실제 완공의 한 시드 기제 검증이다.

추가 seed7777도 초기 조건 조작 없이17일차에 해금됐다. 주문 조건을 충족한 tick44433에
8000원 지출(잔고685), 기존 슬롯을 기다려44462 착공(required18000),49811 완공이다.
인구33/전체 건설 시작1339/부적격 노동0/no_path0/회계12871/hash125e6d9b.
이 시드도 연속/중간 저장 재개 JSON 전체가 일치한다. 이는 또 하나의 완공 사례이지
두 시드로 성장 효과를 추정한 결과가 아니다.

단위 회귀는 네 방향 footprint/문/승강장, 벽 밖 타일 보존, 회전 역 작업점이 완공 후에도
바닥으로 남는지, 학생 노동 금지, 지역 국고/유출 회계, 부족한 돈/막힌 땅/방향 거부,
저장 후 동일 완공과 logic80 기본값 보충을 검증한다. 짧은 노동량3을 쓰는 별도 단위
회귀는 완료 처리의 테스트일 뿐이며 정상 공기 증거로 쓰지 않는다.

역은 시장 명령 없이 자동 건설되지 않는다. 완공 건물은 전용 platform 자원을 갖지만
아직 열차 운행·노선·승하차·수단 선택은 없다. 따라서 이 검증은 다중 마을의 교통 계층,
혼잡 개선, 역 사용률 또는 인구 증가 효과를 입증하지 않는다.

## 기존 계측 도입 이력

관측 전용 schema61, 로직 v57 유지. `transportStats.today`는 진행 중인 날,
`history`는 완료된 최근 14일이다. `statsHistory[].transport`는 전날 요약이며 중첩된
`day`가 실제 계측 날짜다. OD는 목적·32칸 격자 출발/도착·차량 여부 키로 집계한다.
차량 여부는 기존 이동 규칙의 `hasCar`와 같은 뜻이며, 도로·주차 선택을 새로 만들지 않는다.

`walkingTicks`는 그 날 실제 전진에 사용한 tick 수다(차량의 여러 칸 전진도 tick당 1).
`completedWalkingTicks`는 그 날 도착한 전체 관측 여정의 소요 tick 합이다. 자정을 넘는
여정은 두 값의 집계 구간이 다르다. 구 세이브의 출발 미관측 여정은 `partialArrivals`로
구분하며 평균 완료 시간에 섞지 않는다. 경로 길이 0인 행동 시작도 출발 수와 별도다.
