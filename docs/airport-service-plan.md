# #32 R-B 공항: 수요부터 실제 도착까지

상태: 설계 제안, 아직 공항 기능을 구현/완료한 것이 아니다. 분기 기준039bc8e는 PR172를
포함하며, 부모의 검증/병합과 분리해 진행한다. localhost:3000과 라이브 저장은 건드리지 않는다.
공항 언락/에셋/통계만으로 운항 완료를 대신하지 않는다. 수도·국가·정치·외교·전쟁은
#32의 별도 잔여 요구이며 이 문서가 그 범위를 줄이지 않는다.

## 확인한 코드와 연결 위험

- `logic.tiers[3]`: 대도시 문턱120명. 관할 등급은 `governmentFor`가 권위이며 이웃의
  등급이나 국고를 빌려 해제/건설하면 안 된다.
- `zoneAllowedTypes` → 유상 zone → project 노동 → `addBuilding`이 실제 건설 경로다.
- `chooseVisit`/고용주 배정은 `sameRegion`/BFS를 선행한다. 보행 불가 목적지를 일찍
  버리면 바다를 건너는 공항이 있어도 아무도 이용하지 않는다.
- `startAction`과 `chooseRailJourney`는 보행 경로가 존재한다는 전제가 있다.
  비행 구간을 walking 경로로 넘기면 물/산 위에 보행 마모와 인사가 발생하는 오류가 된다.
- `transport-stats`의 municipalVisit은 실제 도착 시에만 세고, 미완료 출발/취소는 별개다.
- `rail`의 유한 좌석/실제 열차 좌표/하차 후 취소, #173의 이벤트 등록/1KB 저장 계약을
  항공에도 적용해야 한다. 보행 BFS의 N/E/S/W 좌표 계약은 바꾸지 않는다.

## 근거와 게임에 적용할 부분

1. [FAA, Forecast Review and Approval Instructions (2024)](https://www.faa.gov/airports/planning_capacity/Forecasts-Approval-Instructions):
   현재 활동과 가까운 시점의 근거를 개발 판단에 사용하고, 활동 수준을 투자 계기로
   삼도록 설명한다. 게임에서는 실제 관측한 이동량과 시설 수용량을 분리하고, 임의의
   미래 승객 수를 생성해 건설 근거로 쓰지 않는다. FAA의 실세계 승인 절차를 재현하지는 않는다.
2. [Li, Chow, Guo (2025), Runway capacity expansion planning for public airports under demand uncertainty](https://arxiv.org/abs/2502.02783):
   투자 시점/용량/수요 불확실성을 함께 다룬다. 확인 범위는 공개 초록과 서지정보다.
   여기서는 수요 신호와 공급 용량의 분리 원칙만 참고한다. GBM/Poisson 모델이나 논문의
   수치 결과를 게임의 결정적 수식으로 구현했다고 주장하지 않는다.
3. [Lee et al. (2026), Airport Terminal Passenger Queue Forecasting for Departure Gates and Security Checkpoints, v3](https://arxiv.org/abs/2606.07622v3):
   게이트/검색대의 대기 인원·대기 시간을 서로 다른 관측량으로 다룬다. 확인 범위는
   공개 초록과 서지정보다. 게임에서는 대기열 길이, 승차 수, 실제 기다린 tick을 별도로
   기록한다. Transformer 예측기를 이 게임에 넣거나 논문의 성능을 달성했다고 하지 않는다.

이하 알고리즘/수치는 게임 설계 선택이며 위 문헌이 그 수치를 입증하는 것은 아니다.

## 구현 계약 제안

### 수요와 유상 건설

- 관할 대도시이고 다른 마을이 존재해야 airport 건설 후보가 될 수 있다. 각 마을은
  자기 조건으로 판정한다. 상대 마을의 공항도 해당 관할 조건/비용/노동을 충족해야 한다.
- 최근 실제 마을 간 장거리 출발 수와 거리 총합을 관할별로 관측한다. 미완료 출발,
  실제 도착, 지상 우회 시간은 분리한다. 도달 불가 후보를 성공한 여행으로 세지 않는다.
- 기존14일 이동 관측창과 같은 유한 기간을 사용한다. 시간 경과만으로 누적 수요가
  영원히 커지는 대신, 기본값/문턱을 파라미터화하고 통제 fixture와 자연 성장 표본으로
  조정한다. 구체 문턱은 구현 전 계측/리뷰에서 확정한다.
- 해제는 무상 공항/비행기를 생성하지 않는다. zone 비용은 해당 국고에서 외부 유출로,
  공사 진행은 근로 가능한 실제 현장 주민의 노동으로 처리한다. footprint는 대학12×10보다
  큰 terminal/runway 조합을 사용하고 회전·도로·다리·기존 주택·예약 공터를 보존한다.
- 건설비에는 초기 운항 설비를 포함한다. 첫 운항 모델은 현재 공공 철도와 같은
  자본비용 기반 무임 공공 서비스다. 항공사·유료 티켓·연료·조종사 고용까지 구현한
  모델로 표시하지 않는다. 이를 도입할 경우 별도의 폐쇄 회계 계약과 공급 모델이 필요하다.

### 경로 선택과 승객 상태

- 지상 경로가 가능한 경우 기존 보행/자가용/철도 선택을 유지한다. 항공 후보는
  출발 공항 접근 BFS + 실제 시간표 대기 + 비행 + 도착 공항부터 목적지 BFS로 평가한다.
  단순 공항 간 거리만으로 항상 비행을 고르지 않는다. 동률에서는 기존 지상 선택을 보존한다.
- 보행 불가여도 양쪽 공항에 각각 접근/이탈이 가능하면 항공 후보를 검토한다.
  방문 목적지/고용주/실제 행동 시작의 도달 가능성 판정을 공통 여행 질의로 맞춘다.
  공항 없는 기존 세계는 경로/RNG/후보 해시를 유지해야 한다.
- 일반 승객 행동(근무/학습/소비/교류/여가)을 대상으로 한다. 개척단·화재 대응·공사·
  보호자 동행·실물 배송은 기존 특수 상태를 보존하며 이번 항공 모드에 몰래 태우지 않는다.
- 상태는 access → waiting_flight → flying → egress → 실제 시설 도착이다.
  탑승은 공항에 실제 도착한 순서, 동률 sim ID. 용량 초과자는 다음 운항을 기다린다.
- 비행 구간은 결정적인 항공 경로의 좌표를 순서대로 진행한다. 지형의 보행 가능 여부와
  무관하지만 경계 밖으로 나가지 않는다. 승객 좌표는 항공기를 따르며 지상 인사/마모/
  분실물 습득을 발생시키지 않는다. 좌표 점프를 시설 도착으로 처리하지 않는다.
- 일일 생애 전환/취업 변경은 기내 승객을 지상으로 순간이동시키지 않는다. 예약 해제 후
  목적지 공항 하차 시 행동을 취소한다. 모든 상태에서 중간 저장 재개가 동일해야 한다.

### 네트워크·운항 중단·자원 상한

- 공항 쌍마다 무조건 새 비행기를 만드는 완전 그래프는 피한다. 실제 수요가 있는 연결과
  유한 기체/좌석만 운영하고, 노선 수/기체 획득이 자본비용에 대응하도록 설계를 확정한다.
- 화재 등 터미널 폐쇄는 신규 탑승을 막는다. 이미 비행 중인 승객은 기체에 남아 안전한
  공항에 도착한 뒤 내린다. 도착 공항이 제거/불통이면 출발 공항 회항, 양쪽 불가면
  기내 대기/우회 가능 공항 질의를 사용한다. 바다 위 하차나 임의 지상 좌표 이동은 금지한다.
- 네트워크/시간표/기체/대기열은 저장 상태이고 이벤트 payload에는 경로 전체나 전체
  후보 공항 목록을 넣지 않는다. 새 이벤트는 발행과 동시에 등록/실제 Storage 검증을 한다.
- 항공 접근 BFS 비용을 계측하고 같은 질의에서 선택한 경로를 재사용한다. 장기 캐시나
  A*로 기존 경로 계약을 바꾸지 않는다. 시간표 주기가 지나치게 많은 질의를 만들면
  원인과 반례를 먼저 측정한다.

## 완료를 입증할 검증

1. 로컬 tier/다른 마을/실제 수요 경계, 유상 건설·초과 지출 방지, default 노동 완료,
   대학보다 큰 footprint4방향, 부지 소유/예약/도로와 기존 시설 보존.
2. 짧은 지상 이동은 지상 유지, 공항 접근/대기 때문에 비행이 느린 경우 제외,
   바다로 단절된 두 지역의 실제 방문/근무, 만석 대기 및 양방향 승하차.
3. access/waiting/flying/egress 각각의 저장 재개, 기내 진학·퇴직·사망·목적지 제거·
   화재 중단/복구·회항, 취소 후 예약/승객 ID 유령 제거, noPath/취소 계측.
4. 실제 유상 건설로 연 두 공항에서 개통 후30일 양방향 운항. 초기 건설/수요 통제는
   명시하고 자연 성장 빈도 주장과 분리한다. 매 tick 회계, 실제 도착, 모든 이벤트 저장을 검사한다.
5. 구버전 저장 migration 무드로우/무상 건설 없음, 공항 없는3시드 불변, 전체 회귀/CI,
   인구200 비용 비교, 실제 브라우저에서 공항·항공기·대기/탑승 표시/재접속.

## 다음 설계 리뷰에서 확정할 항목

- 수요 단위/창/문턱, 부지 크기와 회전 작업 위치, 자본비용/노동량.
- 기체 수와 노선 수의 유한 계약: 노선당 무상 기체가 생기는 구멍을 막을 것.
- 목적지 후보 중력 가중치에 거리와 시간 중 무엇을 유지할지: 현재는 실제 보행 거리이며,
  비행으로 넘어갈 때 몰래 시간 가중치로 바꾸지 말고 공개된 규칙과 테스트를 정할 것.
- 양 공항 불가 시 물리적 대기/회항 상태와 제거/사망 정리, 공항 도착과 실제 목적지 도착의 구분.

이 미확정 항목을 건너뛰고 공항 완료를 선언하지 않는다.
