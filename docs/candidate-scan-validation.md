# #97 후보 수집 최적화

기준 main `328458d`, 최적화 전 오라클 커밋 `f056e81`. 먼저 후보 배열 전체(순서,
점수·보정 포함), action_started, 전체 이벤트, 세계 해시를 인구10/50/200에서 고정했다.
최적화 후 모든 기준값이 같다. RNG·행동·스키마·로직 버전은 바꾸지 않는다.

## 줄인 작업

- 자기 집 행동은 시설 ID 인덱스에서 조회한다. 시설 배열 교체/추가 시 기존 타입
  인덱스와 함께 재구축한다. 인덱스는 저장하지 않는다.
- 동일 결정에서 같은 시설의 예약·쿨다운을 한 번만 조회한다. 자기 예약은 허용한다.
  다른 심/다음 결정으로 캐시를 넘기지 않는다. mall의 자원 종류 필터는 행동별로 유지한다.
- 만석·쿨다운/종류 필터로 후보가 없는 시설에는 계획·기억 보정을 계산하지 않는다.
- 거리 외의 욕구/성향/기분 성분은 행동별로 한 번 계산한다. 정수 곱셈·나눗셈 순서는 같다.
  일반 후보의 객체 필드는 명시적으로 생성해 반복 spread를 제거한다.

상위K·거리 가지치기·점수 문턱 변경은 없다. 가능한 후보는 전부 기존 순서로 점수화한다.

## 벤치

명령: `node bench/popscale.js --pops 200 --days 1 --reps 3`
시드20260831, 워밍업1일, 측정1일, best-of-3. 같은 머신에서 순차 실행했다.

| 버전 | ms/일 | tick/s | µs/sim-tick | 결정·BFS 호출 | BFS ms |
|---|---:|---:|---:|---:|---:|
| 기존 1회차 | 3591 | 401 | 12.50 | 1494 | 1534 |
| 기존 재측정 | 3527 | 408 | 12.28 | 1494 | 1507 |

재측정 기준 총 시간27.3% 감소, 처리량37.7% 증가. 인구200→199, 시설106,
BFS 방문칸/호출15934는 동일하다. 공유 머신 잡음이 있어 통계적 신뢰구간으로 해석하지 않는다.
합성 부하 fixture이지 성장 월드의 대표값이 아니며 20k tick/s 목표 달성도 아니다.
잔여 큰 비용은 BFS(최적화 뒤59%)로 #98 범위다.

예약조회 횟수 검사를 포함한 전체343개가 통과했다. 이후 main의 연대기/클라이언트 변경
통합 후 저장·급식·후보29개와 빌드도 통과했다. 후보 오라클은 세부 점수·순서까지 보존한다.
localhost:3000 서버와 DB에는 접근/변경하지 않았다.
