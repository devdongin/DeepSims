## 긴급 생존 행동 우선권 (#176)

자율 선택 시 hunger/energy가 기존 needCritical 미만이고 해당 긴급 후보가 있으면,
그 후보들 안에서 기존 점수·동률 규칙으로 선택한다. 사교/여가 성격 가중치 때문에
음식과 돈이 있는데도 영구적으로 식사/수면을 포기하지 않는다. 비용·재고·예약·경로
제약을 우회하거나 자원을 지급하지 않으며, 생존 후보가 없으면 다른 행동을 허용한다.
일반 선택과 사용자 지시는 유지하고 산업 부족분 관측에는 원래 후보 집합을 사용한다.

## 공항 유상 건설 (구현 진행 중, #32)

실제 공항 시설이 사라지면 다음 tick에서 해당 공항 ID를 영구 폐기 상태로 보존하고
airport_removed를 기록한다. 첫 공항처럼 기체가 없어도 처리한다. 임시 사고는 폐기가 아니다.
기존 기체와 탑승객은 삭제/순간이동시키지 않고 기존 중단·회항 절차를 따른다. 새 공항은
다른 ID로 비용과 노동을 다시 지불하며, 활성 부모 공항이 있을 때만 새 노선/기체를 만든다.
폐기 이력을 포함한 누적 기체 수는 누적 완공 수−1 이하이며 자동 재배치/무상 증편은 없다.

로드 시 공항·유상 공사 ID, 노선 끝점, 운항 시계, 기체·회항·승객 상태를 검증한다.
공항 필드가 없던 저장은 빈 망으로 이관하고, 누락된 노선 순번만 기존 ID에서 계산한다.
공사 이력이나 기체가 사라진 부분 저장은 임의 복원하지 않고 오류로 거부한다.

수요·도시 등급은 결제 시 심사한다. 기존 구역 주문과 동일하게 결제된 주문은
취소·환불하지 않으며, 대기 중 수요 감소만으로 투자 승인을 취소하지 않는다.
착공 시에는 공터 점유와 보호 시설 등 실제 건설 가능성을 다시 확인한다.

항공 여정 조회는 실제 도보 접근·출구 경로와 운항 시각표를 비교한다. 물로 분리된
목적지도 양쪽 공항에 도보 접근할 수 있으면 후보 여정을 계산하며, 비행 구간을
가짜 도보 경로로 만들지 않는다. 좌석은 출발 시 배정한다. 주민의 행동 시작·방문 중력·
고용주 배정에 연결하며, 수단 동률은 기존 보행/자동차/철도를 유지한다. 방문 중력과
고용주는 물리 거리를 사용하고 운항 시간은 수단 선택에만 사용한다.
대학 등록도 실제 항공 접근 가능성을 확인하고 관할에 등록금을 낸다. 운항 중단으로
통학할 수 없는 대학에는 등록금을 받지 않는다. 학생은 통학만 하며 고용되지 않는다.

접근 보행→실제 게이트 대기→유한 좌석 탑승→항공기 좌표 이동→공항 하차→이탈 보행→
목적 시설 도착을 실제 tick으로 실행한다. 접근 보행 후 항공을 실행하므로 그 tick의
게이트 도착을 관측한 뒤 출발한다. 기내 재지시는 거부하고 진학/고용 변경은 하차 후
취소한다. 공항의 일시 폐쇄는 기존 원거리 고용을 해제하지 않지만 실제 제거는 재심사한다.
경찰 순찰·공사·개척단·배송·동행은 항공에 태우지 않는다. 비행에는 지상 마모/인사가 없다.

항공 통계는 출발/기내 정수 좌표 이동 거리/대기/최종 도착을 구분한다. 공통 pathTiles는
계획된 물리 경로 길이이며, air에서는 접근 보행+항공 직선 거리+이탈 보행이다. 실제
walkedTiles에는 보행만, airDistance에는 tick별 기체 이동 거리만 들어간다. 공항 하차나
회항을 municipalVisit 성공으로 세지 않는다. 하차 때 목적 시설·예약·실제 BFS를 재검증한다.

해당 마을의 대도시 등급과 다른 주민 마을이 필요하다. 최근14일(오늘 포함)의 실제
마을 간 도착 중 중심 거리 `transport.longTripMin` 이상인 마을 쌍의 도착 합이
`airportTripsMin`(기본12) 이상이어야 건설을 지시할 수 있다. 시도/취소를 성공으로
세지 않으며, 지상 단절 마을의 최초 수요 형성은 아직 별도 미해결이다.
국고30000/기본 노동60000,20×12 부지,기체 속도8/좌석8/정차10/환승10은 조정 가능한
게임 기본값이다. 유상 공사가 실제 완료돼야 공항을 등록하며 첫 공항은 기체0대,
이후 공항마다 이전 공항 하나에 연결되는 기체1대다. 기존 주민에게 공짜 돈이나 직업을
만들지 않는다. tick의 입력/로직 적용 뒤 항공 실행, 공사 완료 단계의 등록 순서다.
현재 유상 건설과 주민 방문/근무/귀가 및 서버/화면 상태가 연결됐다. 스냅샷과 배치는
같은 제한된 항공 투영(공항·노선 끝점·기체 좌표/상태·탑승/대기 인원)을 사용한다.
주민 투영에는 항공 여부만 보내고 전체 여정/보행 경로/공사 ID는 보내지 않는다.
지도는 기내 주민 대신 기체 운항 상태를 표시하며, 접근·이탈 중 자가용을 표시하지 않는다.
건설 창은 선택 관할의 서버 수요 판정과 현재 비용을 보여주고 최신 배치로 갱신한다.
동일 지형 재접속에서도 기체와 주민 표시를 새로 맞춘다. 공항은 현재 기본 타일 외관이며
전용 외관 보강, 신규 이동의 장기 검증, 자연 수요·지상 단절 첫 공항의 투자 근거는 남아 있다.

별도 임시 DB/포트의 실제 Chrome 검증은 탑승1명/게이트 대기1명, 실시간 상태와 건설
제한, 재접속·새로고침을 확인했다. 이 fixture는 이미 준비된 공항/주민 상태를 쓰므로
자연 성장이나 실제 유상 공항 건설의 증거로 사용하지 않는다.

## 0.5 관람 속도 (§20 · §22.1)

### 확장 이벤트의 저장 경계 (#173)

부지 재배치·공사 이주 대기·가구 이주 출발·고용 사무실 계획·마을 부지 배정 및 철도
개통/승하차/중단/재개의 실제 이벤트는 저장 허용 목록에 등록한다. 목록 누락으로
시뮬레이션이 진행됐는데 원자 저장 커밋이 실패하던 결함을 수정한다. 미등록 이름과
1KB 초과 payload 거부는 그대로 유지한다. 시뮬레이션 선택이나 저장 필드를 바꾸지
않으므로 스키마/로직 버전은 유지한다.

### 무직자의 재취업 (#151)

무직자는 이미 가진 직장을 지키기 위한 적성 개선 문턱을 적용받지 않는다. 실제 매출이나
생산 수요와 빈자리가 있어야 하며, 학생·미완료 학위·나이 자격 검사는 그대로다. 직무
적성에 따른 순위와 채용 확률도 유지한다. 기존 근로자의 이직에는 계속 적성 개선을 요구한다.
무직 숫자를 낮추기 위해 일자리나 돈을 즉시 만들지 않는다.

### 고용주와 출근 (#112, 구현 검증 중)

직업을 가진 주민은 해당 업종의 실제 시설 하나에 고용된다. 최초 배정은 집 문에서
근무지 문까지의 실제 보행 거리 d에 대해 floor(1000000/(d+1)) 가중치로 추첨한다.
시설별 한 후보이며 좌석 수나 시설 배열 순서는 확률을 늘리지 않는다. 선택지는 시설 ID
순이고, 둘 이상일 때만 rngSim을 한 번 소비한다. 한 곳이면 추첨 없이 배정한다.

이후 위치·매출·일시 만석·화재가 달라져도 다른 가게로 출근하지 않는다. 전직·학생 전환·
시설 소멸·집에서 도달 불가가 되면 고용을 해제하고 자격이 있을 때만 다시 찾는다.
학생/19세 미만/미완료 학위 과정은 고용되지 않는다. 근무 후보와 부족 관측 모두 고용주로
제한하고, 경찰 순찰은 소속 경찰서의 마을에서 한다. 공공 급여도 고용 시설의 재정이 낸다.
기존 채용·직업별 정원·매출 기반 임금 규칙은 유지하며 배정 자체가 돈이나 일을 만들지 않는다.
은퇴자도 고용 대상이 아니다. 고용 시작 로그는 후보 수·총 가중치·선택 거리/가중치·난수만
보존해 사업장이 많아져도 저장 payload 1KB를 넘지 않는다. 산업 진단은 실제 사업장 고용
인원을 관할별로 집계하며, 거주지 직업 인원과 고용주 없는 직업 보유자를 별도로 보여준다.

주민 배치는 위치·욕구 등 변동분과 달라진 정적 정보만 합쳐 표시한다. 학위 완료/수업료,
마을 이동, 성향·능력 변화도 정적 변경 감지에 포함한다. 화면에서 쓰지 않는 경로 배열은
전송하지 않지만 역 접근/하차 후 보행 여부는 남겨 차 아이콘으로 잘못 표시하지 않는다.
사라진 주민의 표시 캐시는 제거한다. 이 전송 최적화는 실제 행동·시간·저장 규칙을 바꾸지 않는다.
새 배치 형식을 지원한다고 알린 연결에만 분리 전송하며, 기존에 열린 구버전 화면에는
전체 주민 표시 데이터를 계속 보내 호환성을 유지한다.

### 주거·공터 부족에서 개척 청원을 낸다 (#32, 구현 중)

실제 침대가 차고 빈집·지역 공터·예정 주택이 없으면 부족일을 센다. 근무 가능한 성인이
`founding.minSettlers`명 이상이고 `founding.petitionDays`일 연속 부족해야 청원을 낸다.
학생·19세 미만·아직 끝나지 않은 대학원 과정의 주민은 노동 파견 후보에 들어가지 않는다.
여건이 개선되면 대기 청원을 철회한다. 내구 명령 `found_village`로 승인/거부하며 승인 시
현재 부지·보행 연결·주거 비용을 다시 확인해 계획을 저장한다. 거부되면 부족일을 새로 센다.
승인만으로 돈·주민·건물·마을이 생기지 않는다. 다음 tick에 조건을 다시 확인해 기존 국고로
공사비를 지급하며, 지정 성인이 실제 현장에 있어야 공정이 진행된다. 인력이 학생으로 바뀌거나
부지가 무효해지면 미완공분을 환불·취소한다. 완공 집은 주민이 실제 도착할 때까지 이민이나
자동 이사에 내주지 않는다. 파견 성인과 함께 이주할 배우자·자녀·학생 가족을 계획에 포함하고,
2명까지 주택, 더 큰 가족은 성인 보호자가 있는 8인 아파트로 실제 비용과 공정을 계산한다.
완공 후 가족은 기존 집 앞에 모여 욕구가 이동을 감당할 때 한 칸씩 걸어간다. 전원이 배정된
집 앞에 도착한 뒤에만 거주지·마을 소속을 바꾸고 새 마을을 만든다. 이주는 노동이 아니다.
가족 변경·주택 상실·이동 경로 단절 시 취소하며 완공 집은 보존한다.
새 마을의 국고는 0에서 시작한다. 다음 일일 평가에 지역 성인 유권자가 근무 가능한 성인
시장 후보를 뽑으며, 선거·복지·육아 지원·재정 정책은 해당 마을 주민과 잔고를 기준으로 한다.
소득세·차량 취득세·의료/식사 지원은 거주지, 공공 임금·등록금·임대료·시설 매출은 시설
소재 마을 국고에 귀속한다. 다른 마을 잔고를 복제하거나 대신 소비하지 않는다.
봉사·행사·방치 화재·공해는 시설 소재 마을, 순찰은 소속 마을의 평판에 반영한다.
지역 청원과 평판 감쇠도 독립적이며 재정 판단은 해당 마을의 관측 이력만 읽는다.
전역 이력은 전체 인구·국고 합계를 유지하고 과거 전역 값을 지역 관측으로 소급하지 않는다.
시정 패널에서 마을을 선택하면 그 마을의 국고와 정책을 읽고, 정책 입력도 그 마을에만
내구 기록한다. HTTP와 tick이 같은 허용 필드/대상 검증을 사용하며 잘못된 마을로 요청하면
원래 마을로 대신 적용하지 않는다. 기존 마을 ID 없는 입력은 원래 마을 정책으로 유지한다.
도로·도시 성장/이민 및 양방향 왕래는 아직 연결 중이다.
근거/정확한 조건은 PLAN.md #32 및 이슈 R-C다.

### 실제 식료품을 재배하고 시장까지 운반한다 (#76)

장보기는 시장/상가의 유한 `groceryStock`을 소모한다. 재고가 없으면 돈과 물건 모두
움직이지 않는다. 부족 재고는 후단에서 재입고 주문을 만들고, 시장 매출의 구매 예산은
임금으로 먼저 소진되지 않게 확보한다(같은 시설 지갑 안의 용도 지정이며 이중 자산이 아니다).
성인은 유상 주문이 있을 때 자기 집에서 식료품을 재배하고, 보유 비축3개를 제외한 잉여를
시장까지 운반해 실제 남은 자금·공간만큼 판다. 학생·미성년자·대학원 미졸업자는 재배/공급
노동을 할 수 없다. 기존 취미 텃밭은 생활 활동으로 유지한다. 초기/구 저장의 개장 재고는
유한한 경계 재고로 명시하며, 신축 매장은 식품을 받지 않고 국고에서 실제 이전된 운전자금으로
공급자에게 산다. `foodSupply` 원장과 생산·운반·구매 이벤트에서 관측한다.

### 일상 위험 사건 사이에 회복 시간을 둔다 (#89)

질병·화재의 일일 위험 드로우는 같은 수와 순서로 후보를 만든다. 디렉터는 후보가 있을 때
최소 2일 간격, 최근 7일 최대 3회, 직전 사건 대상의 실제 회복을 확인한 뒤 해시 순으로
최대 하나를 배치한다. 국고·부·인구로 강도를 조절하거나 주민을 직접 치료하지 않는다.
전염·진료·소방·자연 회복은 기존 행동대로 진행한다. `storyteller.history`에는 최근 14일
후보 수·유형·배치 또는 보류 사유가 남고, 빈 후보에서 사건을 억지로 만들지 않는다.

### 일별 이동 수요를 기록한다 (#48)

이동 규칙은 그대로 두고 성공한 출발의 목적·32칸 격자 OD·거리·차량 이동, 실제 이동 tick·칸,
도착·취소와 도로 이용을 기록한다. 이동 중 저장도 같은 관측을 이어가고, 구 저장의 이미 시작된
여정은 전체 시간이 알려진 도착과 구분한다. 스냅샷 `transportStats`와 내보낸 리포트의
`transport.today/days14`, `stats14[].transport`에서 확인한다. 혼잡·주차는 아직 모델이 없어
이 통계로 피해가 0이라고 주장하지 않는다.

### 실제 수요가 공방·연구소·창고를 연다 (#63, Draft)

도시 시설이 충분히 누적되면 공방, 주민의 실제 공부가 쌓이면 연구소, 장거리 이동이 쌓이면
창고 산업이 열린다. 인구 수만으로 열리지 않고 한번 열린 산업은 다시 잠기지 않는다. 국고와
공터가 있으면 시민이 기존 건설 행동으로 시설을 완공하고, 그 뒤 적성이 맞는 주민이 장인·연구원·
물류 담당자로 전직한다. 신규 주민을 만들거나 불만 수치를 낮추지 않는다. 관측은
`world.unlockedIndustries`, `industry_unlocked`, 시설·직업·임금 이벤트다.

### 학교와 진학 (#96: 세이브55·로직50에서 도입)

7세부터 초등학교, 13세 중학교, 16세 고등학교로 옮긴다. 학생은 평일 낮에 맞는 학교로
가서 수업을 듣는다. 통학 시간은 학업으로 세지 않고, 학교에서 임금을 받지도 않는다.
지능은 실제 수업을 통해 천천히 자라며 식사·건강이 나쁘면 성장이 막힐 수 있다.
19세 이후에는 지능과 성향을 바탕으로 대학/취업을 선택한다. 통학 가능한 대학이 없거나
본인과 동거 부모의 등록금이 부족하면 진학을 보류한다. 학위는 나이나 학교 건물 존재가 아니라
최소 수학 기간과 실제 누적 수업량으로 판정한다. 학부 졸업 후 석사, 석사 졸업 후 박사에
진학할 수도 있다. 비진학자는19세부터, 재학생은 최종 선택 과정 졸업 후에만 취업한다.
학비가 없어 등록을 보류한 재학생도 자동 취업하지 않는다. 학령 인구에 비해 교실이 부족하면 국고와 공터가 허용하는
범위에서 학교 공사가 시작된다. 근거는 사용자 #96 학제 지시이며 별도 실증 모델로 주장하지 않는다.
튜너블: `education.*`, `actions.study`, `zone.costs`, `construct.requiredByType`, `development.*`.
학생 소득 제거 후 고정 스냅샷에서 위급 허기 증가가 관측되어 #57 지원 행동과 함께 재검증한다.
학교별4방향+내부15종과 실제 로더를 연결했다. #57 공공 식사와 함께 최종 회귀332개를 통과했다.

새로 이사 오는 플레이어는 성을 포함한 전체 이름을 입력한다(#103). 이름·성별·MBTI 세
항목을 고르는 흐름은 같고, 입력한 이름 앞에 무작위 성을 붙이지 않는다. 옛 세이브의 이름은
그대로 유지한다. 근거는 사용자 이름 중복 버그 보고이며 별도 수치 튜너블은 없다.

계획 중심지(#119)는 공터 메뉴에서 지정할 수 있다. 국고에서 계획 비용이 지출되고 사건
기록에 남는다. 새 건물은 시청·시장·계획 중심지 중 가까운 곳을 기준으로 들어선다.
NPC 시장은 재정 리뷰 때 이미 주민이 모여 사는 외곽을 보고 여유 국고로 중심지를 지정한다.
주민을 생성하거나 이주시키지 않는다. 근거는 사용자 도시계획 지시(#119)이며,
튜너블은 `zone.plannedCenterCost`, `zone.centerRadius`, `zone.centerMinResidents`다.
- 상단바 **×1 / ×4 / ×10 / ×20**로 시간이 흐르는 속도를 바꿀 수 있다.
  **세계의 규칙은 그대로**이고 같은 시뮬레이션이 더 빨리 흐를 뿐이라, 결과와 결정성은 배속과 무관하다.
- 기본 ×1에서 1틱은 실시간417ms, 하루1440틱은 약10분이다.
- **기본40일 달력에서 ×20이면 실시간 약20분이 게임1년**이다. 사람이 태어나고 나이 들고 세대가 바뀌는 걸
  앉은 자리에서 볼 수 있는 속도다. 달력은 그대로여서 하루는 여전히 24시간이다.
- 자리를 비워도 세계는 흐른다. 따라잡기 한도240일은 ×20에서 실시간 약2시간, 기본 달력6년이다.

## 1.5 기차역은 이동 수요가 언락한다 (§19.12, 이슈 #52)
- 마을 사람들의 **장거리 이동이 쌓이면** 기차역을 지을 자격이 생긴다. 인구 등급이 아니라
  **이동 수요**가 여는 유일한 건설 타입이다 — 수단이 먼저 주어지는 게 아니라 수요가 수단을 만든다.
- 세계가 매일 스스로 판정한다: 장거리 이동 횟수에서 **차 있는 사람의 이동은 절반만** 세고
  (이미 수단이 있으니까), 평균 이동 거리가 충분히 멀면 수요를 **가중**한다(먼 길일수록 기차가
  경쟁력 있다). 이 수요가 문턱(`transport.stationDemand`)을 넘으면 언락된다.
- 언락은 **비가역**이고, 그 순간까지의 **충족도 %가 항상 관측 가능**하다 — 이분 컷으로
  숨기지 않는다. 언락돼도 역이 저절로 서지는 않는다: 시장이 공터에 건설을 지시하면
  해당 지자체 국고에서 비용을 내고 기존 FIFO·주민 노동으로 완공한다. 기본 비용8000,
  노동량20000(시장 재임 시 기존90% 할인), 크기8×6이며 네 방향 회전을 지원한다.
  연결 가능한 완공 역 두 곳부터 무료 공공 셔틀을 운행한다. 선로는 기존 보행 가능 지형을
  따라 시설·공터·예약 부지를 피해 연결하며, 선로 위 신규 건설은 금지한다.
  주민은 도보 접근·시간표 대기·열차·도보 도착의 예상 시간이 기존 도보/차보다 짧을 때
  선택한다. 정원 초과는 실제 대기하며 환승은 아직 없다. 가짜 직장/여가 자리는 만들지 않는다.
- 역을 지어도 혼잡이 저절로 풀린다고 가정하지 않는다(도로를 넓히면 통행량도 는다는
  Duranton & Turner의 유발 수요) — 그 계측은 #48 동반 과제다.
- 파라미터: `transport.stationDemand`(300) · `stationCarOwnerPct`(50) · `stationDistBoostMin`(60) ·
  `stationDistBoostPct`(25). 관측: `world.transit`, `/api/industry`의 H(운수·창고업) `transit` 필드.
  건설값: `zone.costs.train_station`, `construct.requiredByType.train_station` (logic81).
  기존 세이브는 비용/노동량 기본값만 보충하고 이미 시작한 프로젝트 노동량은 유지한다.
  최신 통합본은 schema74/logic92이며, 양쪽 저장 버전68 충돌을 구분해 개척 필드와
  관계·습관 집계를 함께 복원한다. 역 건설 규칙은 logic81 도입 시점과 같다.
  `railSpeedTiles`4·`railDwellTicks`10·`railCapacity`8은 노선 개통 시 고정한다.
  열차/선로는 역 건설에 포함된 무료 공공 기반시설로 취급한다. 운임·운영비·직원·연료·
  신호/충돌·혼잡 효과는 모델링하지 않는다. 가족 이주·아동 진료 동행·공공 작업은 기존 이동을 유지한다.
- 공터는 보행 마모와 공공 도로 공사로부터 보호한다. 일반 미사용 공터는8×6이며,
  예약/진행 중 건물은 실제 회전 footprint(대학12×10 또는10×12), 이미 놓인 선로도
  보호한다. 다른 지자체 소유 부지도 동일하게 보호한다. 이미 포장된 지형을 자동으로
  잔디로 되돌리지 않으며, 기존 중심지의 미사용 부지 재배치 규칙은 유지한다.
- 주거 계획은 집이 들어갈6×5 부지를 배제하지 않는다. 본마을과 새 마을 모두 아파트가
  들어갈 자리가 없으면 더 작은 주택을 선택하되, 실제 발자국과 예약 부지를 확인한다.
- 사망·이민으로 주민이 제거될 때 현금도 세계 밖으로 나가므로 해당 잔액을
  `externalOutflow`와 제거 이벤트의 `cashOutflow`에 기록한다. 현재 모델에는 세계 안의
  상속 분배가 없으며, 생존자나 국고에 임의로 지급하지 않는다.
- 공공직 채용/감원 우선순위는 공무원→교사→의사→경찰→간호사→소방관→정치인이다.
  저장 파일의 객체 키 순서가 바뀌어도 채용 대상과 순서는 달라지지 않는다.

## 1.4 혼자 있으면 먼저 말을 건다 (§22.6)
- 사교하러 갔는데 아무도 없으면, 같은 자리에서 **다른 일을 하고 있는 사람에게 먼저 다가가 청한다.**
  옆에서 밥 먹던 사람도 이제는 말을 걸어볼 상대다.
- 상대는 **응할 수도, 거절할 수도** 있다. 친할수록·자기도 사람이 그리울수록 잘 응한다.
  사이가 나쁜 상대에게는 아예 말을 걸지 않고, 자는 사람은 깨우지 않으며, 아이에게는 청하지 않는다.
- 응한다고 하던 일을 팽개치지는 않는다. **그 자리로 마음이 기울 뿐**이고, 하루에 같은 사람에게
  거듭 조르지도 않는다.

## 1.3 병원에 낸 돈은 마을 살림으로 간다 (§22.4)
- 병원·시청·학교·경찰서·소방서에 낸 돈은 그 건물에 쌓이지 않고 **마을 살림(국고)** 으로 간다.
- 의사·교사·경찰 같은 공공 일자리의 월급은 **그 살림에서 나간다.** 살림이 비면 월급도 덜 나온다.
- 카페·식당의 월급은 여전히 그 가게가 번 돈에서 나오고, 사무직·공장은 마을 밖에서 벌어온다.

## 1.2 태어나고, 자라고, 죽는다 (§22.2)
- 아기는 **0세로 태어난다.** 일하지 않고 먹고 자고 놀며 자라며7세부터 학교에 간다.
  학생은 공사·증축·공적 업무에도 참여하지 않는다. 비진학자는19세부터, 진학자는 선택한 최종 학위 졸업 후 일한다.
- 사람은 **죽는다.** 정해진 나이에 일제히 죽는 게 아니라, 나이가 들수록·체력이 약할수록·
  아플수록·오래 굶었을수록 그날 죽을 가능성이 조금씩 커진다. 아무리 나빠도 즉사하지는 않는다.
- 배우자를 잃으면 남은 사람은 깊이 상심한다. 시장이 죽으면 그 자리는 비고 다음 선거에서 다시 뽑는다.

## 1.1 손님이 몰리면 누군가 그 일을 하러 간다 (§21.3)
- 식당·가게에 손님이 꾸준히 오면, 그 일을 **잘할 수 있는 사람**이 하던 일을 그만두고 옮겨간다.
- **아무도 요리사나 점원으로 태어나지 않는다.** 그런 직업은 수요가 만든다.
- 지금 하는 일보다 확실히 더 잘할 때만 옮기고, 자리가 차면 더는 옮기지 않는다.
- 다만 서비스업 임금은 **그 가게가 번 돈**에서 나오므로 사무직보다 불안정하다 —
  그래서 옮긴 사람은 저축이 더디고, 마을에 집이 덜 지어지기도 한다.

## 1.0 곤경에 처한 사람을 돕는다 (§21.2)
- 사교하다가 만난 상대가 **돈이 거의 없으면 나눠준다.** 한집 식구에게 가장 잘 주고,
  친구·지인 순으로 덜 주며, 사이가 나쁜 상대에게는 주지 않는다.
- 주는 쪽도 여유가 있어야 준다 — 자기가 빠듯해지면서까지 주지는 않는다.
- 은퇴자는 벌이가 없어 저축이 마르면 굶는데, 이 나눔이 그들의 지갑을 받쳐준다.

## 0.9 사람마다 잘하는 게 다르다 (§21.1)
- 심마다 **체력·손재주·지능·사교성** 네 가지 능력이 있다. 타고나는 값이라 사람마다 다르다.
- 자기 직업이 요구하는 능력이 높으면 **더 번다.** 다만 차이는 완만해서(±20%),
  능력만으로 직업 간 격차가 뒤집히지는 않는다.
- 학생이 졸업할 때 **잘하는 쪽 직업으로 기운다.** 정해진 게 아니라 확률이 높아질 뿐이라,
  적성과 다른 길을 가는 사람도 나온다.

## 0.8 사람은 사람이 있는 곳으로 간다 (§20.3)
- 사교하러 갈 곳을 고를 때, **이미 누가 사교 중인 장소**가 더 끌린다. 친구가 아니라 낯선
  사람이어도 그렇다 — 누군가를 만나려면 먼저 사람이 있는 곳에 가야 하니까.
- 그리로 **가고 있는 사람**도 함께 센다. 덕분에 한 곳으로 우르르 몰리지 않고 적당히 나뉜다.
- 자리가 다 찼으면 끌리지 않는다. 가봐야 앉을 데가 없기 때문이다.
- **갈 수 없는 곳에도 끌리지 않는다.** 강 건너나 산 너머라 걸어갈 길이 없으면, 거기 사람이
  아무리 많아도 후보에서 빠진다.

## 0.7 낸 돈은 가게에 남는다 (§20.2)
- 심이 카페에서 밥값을 내면 그 돈은 **사라지지 않고 그 가게의 매출**이 된다.
  예전에는 지갑에서 빠져나가 허공으로 없어졌다.
- 카페에서 일하는 바리스타의 임금은 **그 카페가 번 돈에서** 나온다. 손님이 없어 매출이
  모자라면 임금을 다 주지 못한다 — 가게는 빚을 지지 않는다.
- 사무직과 공공직(의사·교사·경찰 등)의 임금은 아직 마을 밖에서 들어오는 소득으로 본다.

## 0.6 복지는 가장 가난한 사람부터 (§20.1)
- 하루에 도울 수 있는 사람 수는 한정돼 있다. 그 자리는 **잔고가 가장 적은 심부터** 채운다.
  예전에는 심 번호가 낮은 순이라, 번호가 큰 가난한 심은 아무리 굶어도 순서가 오지 않았다.
- 도움을 받은 심은 문턱 위로 올라가 다음 날 자리를 비워주므로, 강제하지 않아도 **순환이 창발**한다.

## 0. 대원칙
- **결정성**: 같은 시드 + 같은 입력 = 같은 세계. 모든 난수는 `rngSim` 스트림에서 정해진
  순서로만 소비. 일별 변주는 rng를 소비하지 않는 `dayHash(simId, day, salt)` 의사확률.
- **이분 컷 금지**: 특성(MBTI 0~100)은 가중치 그라데이션으로, 성향 차이는 확률 차이로
  나타난다. "J형이면 야근" 같은 하드 컷은 두지 않는다.
- **정수 연산만**: 부동소수점 없음. §G 점수식은 2^53 무초과 증명 유지.
- **창발 우선**: 직접 스크립트 대신 압력(욕구·습관·기억·관계)이 행동을 만든다.
- **지표를 누르지 않는다**: 외로움·길 못 찾음·굶주림 같은 수치는 세계가 보내는 신호다.
  수치를 낮추려 계수를 손보는 대신, **사람이 할 법한 행동을 하나 더 준다** — 그 행동이
  문제를 스스로 풀게 하고, 실제로 그렇게 풀리는지 사건 로그로 관찰한다. (사용자 지시)

## 1. 욕구와 행동 선택 (§G)
- 4대 욕구(배고픔·수면·사교·재미) + 기분(mood). 결핍²에 비례한 점수로 행동 후보 경쟁.
- 점수 = 결핍²×16×1e5 / (맨해튼 거리+16) × 성격 × 계획 × 날씨 + 기분/기억/상태/습관 보정.
- 위급(욕구 < needCritical)은 거리 불문 최우선. 대처 행동(음주·폭식·칩거·운동)은
  기분이 임계 이하일 때만 후보 (`coping.threshold`).
- 파라미터: `decay.*`(시간당 욕구 감소), `needCritical`, `actions.*`(비용·지속·회복).

## 2. 생활 리듬 (§17.13/16/17 — 논문 로드맵 P1)
- **크로노타입** (연속값): `(EI×3+JP×5+age×7)%100` → 근무·수면 창을 ±`chrono.maxShiftMin`분
  선형 이동. 아침형/저녁형이 있고, 나이 들면 값이 이동한다(재평가 창발).
- **야근/칼퇴** (의사확률): 야근 확률 = `(100−JP)×chrono.overtimeProbPct/100`. J 성향일수록
  야근이 잦고, 하는 날 길이도 `overtimeMinBase+(100−JP)×overtimeMinSpan/100`분 그라데이션.
  flex 직업(회사원·프리랜서·공무원·정치인)만.
- **교대근무**: 경찰·소방관·간호사는 id 짝홀로 주간(09–18)/야간(22–06)조. 야간조는 낮에 잔다.
- **서카디언 수면 압력** (P1-②, 생리 모델 이산화): 에너지 감쇠가 시각별 가중
  `circadian.energyPct[24]`(심야 150% → 오전 90%). 개인 위상(크로노 오프셋, 야간조 12h 반전)
  반영 — 밤에 대부분 자고, 야간조는 낮에 졸리다.
- **주중/주말** (P1-①, TUS): day%7≥5는 주말 — 일반 직업 근무 없음, 여가 창이 아침부터 확장.
  교대·서비스업(바리스타·프리랜서)은 주말에도 일한다.
- **수면 슬롯**: 개인화된 취침 시간대가 계획에 들어가 수면 타이밍을 끌어당긴다(욕구 주도는 유지).
- **여가 의도** (의사확률): 사교 확률 = `100−EI`. E 성향일수록 어울리는 날이 많고, I도 가끔 어울린다.

## 3. 인지 (Generative Agents 결정적 포팅, §2.5)
- **기억 스트림**: 사건이 중요도와 함께 기록(캡 256, 전순서 퇴출). 행동 선택 시 관련 기억
  상위 K개가 점수를 보정한다("나쁜 기억이 있는 장소는 피한다").
- **회고(reflection)**: 수면 중 그날의 기억을 요약해 상위 통찰 생성 — 연애 성사·합가 재시도·
  동아리 가입 판정도 회고 시점에 일어난다.
- **습관**: 같은 행동×장소 반복이 `habit[행동:장소]`로 누적 → 점수 가산(캡). 반복 음주는
  중독으로 창발한다. (P2-③ 예정: 보상 신뢰도 기반 습관화 — Wood 이중과정)
- **일과 계획**: 기상 시 슬롯 배열(식사>근무>여가>수면) 생성, planFactor로 점수 보정.
- **정보 확산**: 모임 토큰이 대화로 전파("공원 모임 얘기 들었어?") — 아는 사람만 온다.

## 4. 사회 (§17)
- **관계**: 호감도(비대칭) + 상호작용 횟수 → stranger/acquaintance/friend/rival 티어.
- **삼각 폐쇄** (P2-④, Science Advances aax7310): 공통 friend 수 × `triad.perFriendBonus`
  (캡 3) 페어 보너스 — 친구의 친구와는 빨리 가까워진다.
- **대화**: 맥락 가중 주제(험담·기억·직업·날씨·모임·연애소식·가족·정치) — 실명·실내용.
  험담은 청자의 대상 인식(호감도)을 실제로 바꾼다.
- **연애/결혼**: 회고에서 상호 호감·상호작용 문턱 도달 시 교제→결혼(합가·신혼집 수요·
  결혼식 잔치). 파혼도 있다. 부부 별거는 주거 수요로 건설을 부른다.
- **가족**: 동거 부부에게 월간(`society.childCheckDays`) 확률로 자녀 정착(빈 침대 또는
  증축 여력 필요 — 아이가 태어나면 부모가 침대를 짓는 창발). 노화·졸업·은퇴는 새해(연 단위).
- **선거**: `election.intervalDays`마다 인기(받는 호감 합) 상위 2인 결선. 시장은 공사 가속·
  수당. 후보는 D-3부터 유세(사교가 곧 선거운동).
- **동아리**: 습관 문턱 도달 시 가입, 주간 모임 토큰(멤버 전원 인지).
- **질병**: 일일 위험 드로우(굶음·비·저에너지 가중) + 페어링 전염 — 사교가 병을 옮긴다.
  병원 진료(see_doctor) 또는 자연 치유.
- **순찰·분실물** (§17.24/§19.4): 경찰은 근무 시간에 마을 공공시설을 결정적 경로로 순찰하며(문 주변 갈 수 있는 칸을 골라 서고, 길이 막히면 다음 목적지로 넘어간다) 다닐
  때마다 평판을 지킨다(공해의 대칭). 경찰이 있는 마을에선 동전을 주운 심이 성격(TF 가중
  의사확률)에 따라 파출소에 신고하고, 3일 뒤 임자가 없으면 정직한 발견자의 몫이 된다.
- **사건/화재** (§17.20): 매일 시설별 소액 확률로 불이 난다(주방 있는 식당·카페 가중).
  불타는 시설은 못 쓴다. 소방관에게 진압이 위급 후보로 승격 — 진압하면 목격자들의 호감을 얻고
  영웅 기억이 남는다. 아무도 안 오면 하루 뒤 저절로 꺼지지만 마을 평판이 깎인다.
- **이민**: `society.immigrationIntervalDays`마다 빈 침대가 있으면 새 주민 도착. **평판 웨이브**
  (§17.21): 결혼·축제·완공·자녀·선거·모임이 마을 평판을 쌓고(일일 감쇠), 평판이 높을수록
  한 번에 여러 명(1+평판/80, 캡 3)이 온다 — 행동이 도시를 키운다.

## 5. 경제 (§17.15/18.T1 — Lengnick baseline 차용)
- **시정 정책** (§18.T1): 플레이어(시장)가 세율·복지를 조절한다 — 내구 입력이라 리플레이 불변.
  세율을 올리면 국고가 차지만 **납세 때마다 주민 기분이 상한다**(세액 비례 그라데이션) →
  평판·이민이 위축되는 타이쿤 트레이드오프.
- **소득세**: 임금의 `economy.taxPct`% 원천징수 → 국고(`world.treasury`).
- **복지**: 매일 잔고 < `welfareThreshold`인 심에게 국고에서 `welfareAmount` 지급
  (id asc, 하루 `welfareDailyCap`명, 국고 한도) — 가난을 정부가 개입한다.
- **시장 수당**: 국고 지출 — 재정난이면 미지급(창발).
- **집밥 경제**: 시장에서 장보기(groceries) → 집에서 요리가 외식보다 싸다.
- 미완: 기업 임금기금(완전 폐쇄 통화), 소비세. → 이슈 #3 후속.

- **시설 티어** (§18.T3): 읍부터 아파트(침대 8), 시부터 공장(고용 8 — 대신 매일 평판을 깎는
  공해)·상가(쇼핑+여가 복합), 대도시부터 대학(졸업생이 의사·정치인이 될 수 있는 가중 풀).
  전부 시장의 건설 지시로만 지어진다.
- **도시 등급** (§18.T4): 인구 25/60/120 문턱에서 읍→시→대도시로 승격(비가역) — 전 주민이
  축하하고(기분·기억), 평판이 뛰고, 이민 웨이브가 커지고, 상위 시설 건설이 언락된다.

## 5.3 시민의 목소리 (§19.5)
- 심은 잠들 때 그날을 되돌아보며 **불만**을 남긴다 — 어느 카페에서 몇 번 외로웠는지, 굶었는지,
  **급한데 못 한 일이 있었는지**가 — 그때 이유까지 구분해서(돈이 없어서/쓸 수 있는 시설이 없어서 — 만석·길 막힘 포함/시간이 아니어서)
  장소별로 쌓인다. 같은 기억을 두 번 세지 않는다(커서 기준).
- 최근 사흘 안에 같은 불만을 제기한 **사람이 인구의 40%를 넘으면** 청원이 일어나 마을 평판이
  떨어진다(한 명이 열 번 외로워도 한 사람으로 센다 — Granovetter 문턱 모델).
- 불만은 매일 조금씩 **잊힌다**. 문제가 개선되면 사라지고, 지속되면 다시 쌓여 청원이 재발한다.
- 이 불만 기록은 세계 스냅샷으로 나가 개발 로드맵의 근거가 된다 — 마을이 스스로 문제를 말한다.

## 5.4 교통 (§19 R-B)
- 심이 먼 거리를 반복해 다니면(장거리 이동 12회 이상) 돈이 모였을 때 **차를 산다** — 수단이
  먼저 주어지는 게 아니라 수요가 수단을 만든다. 차가 있으면 한 틱에 두 칸씩 움직인다.
- 차 살 때 낸 취득세는 국고로 들어간다. 마을 전체 이동 수요가 문턱을 넘으면 기차역이
  언락된다 — 판정 규칙과 관측은 **§1.5(§19.12)** 참조. 장거리 이동은 횟수와 함께
  **칸수도 누적**돼 거리 분포가 그 판정의 입력이 된다.

## 5.5 지형 (§19 R-A)
- 마을 밖에는 **강**(다리로만 건넌다)·**산**(넘지 못한다)·**언덕·강가·모래 해변**·**바다**가 있다.
  심의 경로 탐색이 이 제약을 그대로 받으므로, 도시는 지형을 따라 자란다.
- 구시가(0..140)는 지형 생성에서 절대 건드리지 않는다 — 기존 세계의 도달성 보존.

## 6. 건설과 도시 성장 (§16.5/B, §17.21)
- 수요 트리거 → 공터에 프로젝트 → 심들이 직접 공사(construct, J형이 부지런) → 완공 시
  이사·합가. 96개 공터로 마을이 스스로 자란다.
- **건설 지시** (§18.T2): 시장이 공터를 클릭해 용도(집·카페·사무소·공원)와 **방향(4회전)**을
  지정한다 — 국고에서 비용이 즉시 빠지고, 심들이 직접 공사한다. 주문은 자동 수요보다 우선.
- **동시 건설**: 국고가 넉넉하면 여러 공사를 동시에 벌일 수 있다(재정이 시공 능력을 만든다).
  다만 계획은 하루 한 번만 세우므로 실제 착공 속도는 수요 조건에 좌우된다.
- **선제 주택**: 빈 침대가 headroom(2) 미만이면 미리 짓는다 — '부족 반응'이 아니라 '여유 유지'.
- **일자리 건설**: 사무직이 책상보다 많으면 사무소 신축 — 고용이 건물을 부른다.
- 갱신 이력: v20 성장 드라이브(§17.21) → v21 화재(§17.20) → v22 등급(§18.T4) → v25 시설 티어(§18.T3)
  → v26 순찰·정직(§17.24) → v27 지형·동시 슬롯(§19 R-A/§19.3) → v28 교통·불만(§19 R-B/§19.5)
  → **v29 불만 망각·원인 분화(§19.7/§19.10)**

## §22.18 산업 수요 — 무엇이 없어서 아쉬웠는가

심이 위급한 필요를 채우지 못했을 때, 세계는 그 이유를 셋으로 갈라 기록한다
(§19.10에서 도입, §22.18에서 산업에 연결):

| 이유 | 뜻 | 산업 수요인가 |
|---|---|---|
| `no_facility` | 갈 곳이 없다 | **그렇다** — 그 행동이 속한 대분류의 수요로 적립 |
| `no_money` | 시설은 있는데 돈이 없다 | **아니다** — 구매력 부족으로 따로 집계 |
| `blocked` | 영업시간이 아니다 | 아니다 — 시간 문제 |

이 구분이 없으면 "돈이 없어 못 먹었다"가 "식당이 모자라다"로 읽힌다. 실제 마을에서
`no_money@eat`이 415건인데 `no_facility`는 0건이므로, 그 오독은 정확히 반대되는
처방(식당 증설)을 낳았을 것이다.

수요는 `world.industryDemand[대분류]`에 정수로 쌓이고, 세계가 이미 집계해 둔
`complaints`에서도 같은 신호를 읽는다(회고 커서 기반이라 틱 잡음이 없다).

**아직 하지 않는 것**: 이 수요로 건물을 짓지 않는다. 자생 착공은 희소성(시설 유지비)이
들어온 뒤의 슬라이스다 — 무한 예산에서 자동으로 짓기 시작하면 마을이 카탈로그가 된다.

## §22.19 일상 수요 — 굶주림만이 산업을 만들지 않는다

§22.18 원장은 **위급한 필요**(욕구가 `needCritical` 미만)에만 걸린다. 그래서 병원을
통째로 지워도 보건업 수요가 **0건**이었다 — 진료는 위급 목록에 없기 때문이다.
도서관도 영화관도 굶주림에서 나오지 않는다.

일상 수요를 **별도 원장**에 모은다. 위급 원장과 합치지 않는다 — 강도가 다른 신호다.

'하고 싶었다'의 기준은 임의 문턱이 아니라 **실제로 한 일과의 비교**다:
- 욕구가 있는 행동(식사·수면·놀이…): 지금 하는 일보다 **더 아쉬웠는데** 갈 데가 없었다
- 욕구가 없는 행동(진료…): **자격이 곧 의사다** — 아픈데 갈 병원이 없으면 그게 수요다

그래서 문턱을 고를 필요가 없고, 욕구가 다 찬 심은 저절로 세지 않는다.

빈도가 높으므로 **심·행동당 하루 1회**로 묶는다. 안 그러면 같은 아쉬움이 매 결정마다
다시 세어져 원장이 틱 잡음이 된다(§22.6에서 같은 실수로 거절 5,924건이 나왔다).

세 갈래가 갈린다 (실측, 40,000틱):
| 세계 | 부재(지어야) | 만석(키워야) |
|---|---|---|
| 병원 온전 | 0 | 0 |
| 병원 철거 | **204** | 0 |
| 병원 자리만 제거 | 0 | **234** |

## §22.20 회고 투표 — 표에 성과가 들어간다

지금까지 투표는 순수 인기투표였다: 두 후보 중 호감도가 높은 쪽. 재임자가 무엇을
했는지는 표에 전혀 안 들어갔다. 사람은 그렇게 투표하지 않는다 — **지난 임기에 내가
겪은 일**로 심판한다 (Key 1966, Fiorina 1981의 회고 투표).

- 유권자는 자기 기억만 읽는다: 굶었다(-3/건), 돈이 없어 못 했다(-2), 복지를 받았다(+3)
- **"나라에 돈이 있는데 나는 굶었다"는 더 화나는 일이다** — 국고가 시민 총현금을
  넘으면 감점이 2배가 된다(사용자 지시: 국고를 쌓아두면 표결에 영향). 절대 금액
  문턱이 아니라 비율 비교라 마을이 커져도 뜻이 유지된다.
- 상한(±40)이 있어 인기를 완전히 지우지 않는다 — 이분 컷이 아니라 가중이다.
- **현직은 재선에 나선다.** 예전에는 후보가 인기 상위 2인뿐이라 재임자가 후보에 못
  드는 일이 잦았고(실측 3회 중 2회), 그러면 심판할 대상이 투표용지에 없었다.
- 새 난수 없음, 각자의 기억만 읽음, 세계 불변 — 결정적이다.

### A/B (60게임일, 같은 시드)
| 정책 | 현직 재선 | 회고합 추이 |
|---|---|---|
| 기본 (세율25·복지550) | 1/3 | 0 → -65 → -117 → +107 |
| 복지 끊고 국고 축적 | 0/3 | 0 → -37 → -472 → **-872** |

복지를 끊은 정부의 회고 감점이 임기마다 깊어진다. 그 세계는 굶주림도 47→78건으로
늘었으므로, 감점은 지표 조작이 아니라 **겪은 일의 기록**이다.

### 아직 없는 것 (다음 슬라이스)
정당·정치 성향은 산업(§22.18)과 같은 원칙으로 **필요에서 생겨나게** 한다 — 같은
처지의 심이 임계 인원을 넘으면. 지금 63명에서 미리 만들면 이름표만 남는다.

## §22.21 먼저 돕기 — 주는 쪽의 외로움이 준다

혼자 남은 심이 말을 걸었는데 상대가 곤경(아픔/허기 위급/복지 문턱 미만)이면 수다가
아니라 **챙김**이 된다. KIND Challenge RCT(4,284명)의 핵심은 **주는 쪽의 외로움이
준다**는 것 — 그래서 회복이 주는 쪽에 붙는다(100%, 곁다리 30%보다 크다). 고마움은
받는 쪽→주는 쪽 한 방향으로만 오른다 — 주는 쪽 호감이 오르지 않아 '아무나 붙잡고
돕기'가 최적 전략이 되지 않는다. 챙김은 수다 스위치(sideTalkFactorPct)와 독립이다.

## §22.22 시장의 재정 행동 — 통치가 시작된다

사용자 진단: "수장이 하는 행동이 아무것도 없으니까 국고가 계속 쌓이는 게 아니야?"
정확했다. §22.20으로 유권자는 심판하는데 NPC 시장은 응답할 행동이 없었다.

시장은 **유권자가 심판하는 것과 같은 조건**(국고>시민총현금)을 보고, 플레이어와
같은 레버를 POLICY_FIELDS 범위 안에서 한 걸음씩 움직인다 (5일 주기 + 유세 시작일):
- 국고가 쌓였고 굶는 사람이 있으면 → 복지 증액 → 문턱 확대 → 감세 (Bohn 1998 반응
  함수의 대칭 확장; Berset 2023의 평활화 — 전액이 아니라 한 걸음)
- 국고가 마르면 → **지출 축소 먼저, 증세는 최후** (Helm & Stuhler 2024: 지자체
  실증에서 세율은 가장 느린 도구다. 처음엔 반대로 짰다가 문헌 확인 후 뒤집었다.
  단 복지를 0까지 깎지 않는다 — 안전망 한 칸은 남긴다)
- 유세 시작일에도 발화 (Nordhaus 1975·Rogoff 1990 정치적 예산 순환)
- 플레이어가 시장이거나 방금 정책을 만졌으면 쉰다 — 내구 입력을 되돌리지 않는다

### A/B (60게임일, 같은 시드)
| | 조정 | 재선 | 굶주림 | 복지 지급 |
|---|---|---|---|---|
| 재정 행동 켬 | 9회 (긴축→증세→완화 순환) | **0/3** | 65 | 180 |
| 끔 | 0 | 2/3 | 59 | 142 |

**정직한 관측**: 문헌 순서(지출 먼저)로 긴축한 시장은 굶주림 시기에 복지를 깎았고,
회고 투표가 그를 전부 낙선시켰다 — 긴축 시장이 표를 잃는 정치경제가 창발했다.
반면 굶주림 자체는 +6건으로 소폭 늘었다. 시장이 잘 통치해서가 아니라 **통치하고
심판받는 구조**가 생긴 것이 이 슬라이스의 목적이다.

## §22.23 공공 임금 완전 보장 + 공기(工期)

**"공무원도 예외없이 일을 하면 반드시 돈을 줘야 되고 공무원이면 국고에서 월급이
지급되어야 해"** (사용자 지시)

'국고 ≥ 0'(89차 ④ invariant)이 공공 임금 지급률 11.2%·교사 실수령 0원의 원인이었다.
폐기했다: 일을 했으면 받는다. 국고가 모자라면 **공채(음수)**로 내려가고, §22.22의
runway 반응이 부채에 작동한다 — Bohn 1998이 정확히 부채 반응 함수다. 폐쇄 회계
보존식은 음수여도 성립한다(국고가 합산 항). 빚이 시작되는 순간 treasury_debt로 알린다.

**뜻밖의 창발**: 임금 보장이 복지를 부분 대체했다. 복지를 끊어도 굶주림이 늘지 않는다
(33→23 실측) — 정부가 적자 재정으로 노동자 주머니를 채우기 때문이다. 민간(시설 매출
상한)은 그대로다 — 매출 없는 가게가 임금을 못 주는 건 정직한 신호고 전직의 동력이다.

**"도로, 건물등은 단숨에 지어져선 안돼"** — 실측: 집 한 채가 게임 10~24시간(×48 관람
0.2~0.5분)에 완공됐다. required가 전 타입 540 동일이었기 때문. 타입별 차등을 뒀다
(공원 3,000 ~ 대학·공장 20,000; 목표 집 ~7게임일). 현장 작업 스팟 4개가 이미 동시
인원을 제한한다. 진행 중 프로젝트는 시작 때 스냅샷한 required를 그대로 쓴다 — 소급
없음. 도로는 발자국 마모로 서서히 생기므로 제외.

## §22.26 공공사업 — 사람들이 걷는 길을 정부가 포장한다

**"도로나 광장등은 정부에서 국고를 써서 해야겠지. 국고가 충분할 때 마을을 성장시키기
위한 도구로 사용한다."** (사용자 지시)

핵심은 대상 선정이다: 정부는 어디를 포장할지 모른다. 아는 것은 세계뿐이다 —
`world.wear`가 발자국의 지도다. 마모가 자연 도로화 임계의 절반을 넘은 자리만,
마모 많은 순으로, 하루 8칸까지 포장한다. **아무도 걷지 않는 곳은 절대 포장하지
않는다** — 수요를 창조하지 않고 창발을 증폭한다(§0.1). 현실의 desire path 포장
관행 그대로다.

- 국고가 시민 총현금을 넘을 때만(§22.20·§22.22와 같은 기준), 차감 후에도 양수 유지
  — **공채로는 포장하지 않는다** (부채는 임금 보장 전용)
- 포장비는 externalOutflow(자재는 마을 밖에서 산다) — construct 노동이 무급인 동안의
  정직한 회계다 (120차 ④)
- **유세 기간에는 투자를 미룬다** — Rogoff 1990: 재임자는 선거 앞에서 '보이는'
  이전지출을 선호하고 투자를 지연한다. §22.22의 유세일 완화 편향과 대칭.
- 즉시 도로화는 §22.23과 충돌하지 않는다: 마모 수백 발자국이 이미 공기(工期)였다.

실측: 신선한 마을은 첫 ~55일을 적자(임금 보장)로 보내 포장할 여유가 없다 — 가난한
마을은 포장하지 않는다, 정직하다. 라이브 세계(국고 127만, 마모 13,680칸)에서는
10게임일에 1회 발화·8칸 포장, 자연 도로화 75→67(포장이 선점). 잔여 후보 434칸
대비 소진이 느린 것은 계측으로 남긴다 — 후속 조정 근거다.

광장(plaza)은 다음 슬라이스다 (120차 B: 새 시설 타입은 A의 회계 검증을 흐린다).

## 경로 탐색 최적화 (#98)

심이 걷는 길의 모든 좌표와 동점 선택 순서는 같다. 탐색 배열의 초기화와 할당을 줄여
계산 비용만 낮춘다. 행동 파라미터나 RNG 소비는 추가하지 않는다.

## 인도와 시설 보호 (#117)

사람이 많이 밟는 곳에는 인도가 생기며 사건 기록과 지도에 바로 표시된다. 공원 안에서는
인도가 가능하지만 공공 차도는 공원·건물 대지와 출입구를 덮지 않는다. 건물 대지와 문
주변에는 보행 마모로도 길을 만들지 않는다. 기존 도로는 유지한다. 사용자 지시 #117에
따르며 마모 임계(`build.wearThreshold`)와 공공사업 비용은 기존 값을 쓴다.

## 반복되는 우회에 길을 요청한다 (#118)

사람이 같은 두 지점 사이를 실제로 여러 번 돌아 걸었을 때 길 민원을 남긴다. 예상 경로나
인구 목표로 민원 수를 만들지 않는다. 근거는 사용자 지시 #118이며, 관측 기준은
`transport.detourMinExtra`, `detourRatioPct`, `detourRepeat`로 공개한다.
여유 있는 NPC 시장은 그 보고를 보고 시설 밖 나무 구간이나 좁은 하천에 연결로를
계획한다. 계획과 완공 사이 공기(`publicWorks.routeWorkDays`)가 있고, 완공 때도 지형과
예산을 재확인한다. 다리는 칸당 `bridgeCostPerTile`, 나무 연결 인도는 기존 포장 비용이다.
건물·공원·출입구·산을 없애지 않고, 개선 가능한 연결로가 없으면 해결한 척하지 않는다.
완공 사건에는 실제 줄어든 이동 거리와 지출이 표시된다. 건축을 위한 도로 철거도 비용과
변경 타일을 즉시 표시하고, 이전 발자국 마모를 지워 곧바로 길이 되돌아오지 않게 한다.

## 배움·근무·나이가 능력을 바꾼다 (#96 1단계)

잠재치와 지금 할 수 있는 능력을 나눈다. 새 심은 나이에 맞는 현재치로 시작하고, 실제로
읽고 공부하거나 일하고 운동한 시간이 해당 능력을 성장시킨다. 굶주리거나 지치거나
아플 때는 같은 시간을 보내도 성장이 막힐 수 있다. 잠재치만 있다고 반드시 도달하지는
않는다. 나이가 들면 성장기에는 자연히 자라고 노년에는 완만히 쇠퇴한다. 근거는 사용자
#96의 성장 요구이며 `development.*` 수치는 조정 가능한 게임 모델이지 임상 수식은 아니다.
기존 세이브의 능력을 깎아 시작하지 않고 그대로 보존한다. 패널은 현재/잠재치를 보여준다.
이 단계만으로 초·중·고·대학이나 천재 출생까지 완료했다고 보지 않는다.

## 천재로 태어나도 자라야 한다 (#96 2단계)

아이가 실제로 태어날 때, 당시 인구×10분의 1 의사확률로 한 분야의 특별한 재능을 갖는다.
그 분야의 잠재치는 일반 최대 99를 넘어 120~150이지만 현재 능력은 갓난아이 수준이다.
배움과 건강·영양이 따르지 않으면 잠재치에 도달하지 못한다. 기존 주민을 소급해서
천재로 바꾸거나 인구·출생 수를 조작하지 않는다. 사용자 #96의 규칙이며 잠재 범위는
`development.geniusMin/geniusMax`다. 천재는 ⭐, 주인공은 ◆로 별도 표시한다.

## 돈이 없어 굶을 때 직접 공공 식사를 요청한다 (#57)

식사값이 없고 장바구니도 비어 위급하게 배고픈 주민은 시청이나 시장을 찾아가 식사를
요청한다. 자리까지 실제로 이동하고 요청을 마쳐야 먹는다. 아동·학생·은퇴자도 이용할 수
있으며, 일하거나 임금을 받는 행동이 아니다. 국고가 외부 식재료값을 지불하고 현금은
주민에게 주지 않는다. 도중에 취소하거나 국고가 부족하면 무료 회복을 주지 않는다.
기존 복지 지급 인원 한도는 바꾸지 않는다. #57의 행동 기반 제안을 구현한 게임 모델이다.

## 후보 계산의 반복 작업 축소 (#97)

행동 선택은 바뀌지 않는다. 같은 결정에서 시설의 빈자리와 행동별 욕구·성향을 재사용하고,
사용 가능한 자원이 없는 시설의 기억 계산을 생략한다. 후보 삭제·상위K 제한은 없다.
예약 캐시는 다음 심이나 다음 결정에 재사용하지 않으며 자기 예약과 쿨다운 만료를 보존한다.
검증·벤치는 `docs/candidate-scan-validation.md`에 기록한다.

## 같은 길을 적은 반복 검사로 찾는다 (#98 후속)

길의 좌표와 동률 우선순위(북·동·남·서)는 그대로다. 방문한 칸의 통행 검사를 반복하지
않고 목적지까지의 경로가 처음 확정되면 나머지 경계 탐색을 멈춘다. 경로 선택 변경이나
지도 캐시는 없으며 지도 수정·크기 변경에도 현재 지도에서 다시 찾는다.

## 아이가 아프면 부모가 실제로 병원에 동행한다 (#71)

19세 미만 아이는 혼자 진료 행동을 하지 않는다. 같이 사는 실제 성인 부모가 아이의
현재 위치까지 간 뒤 병원 자리를 아이 명의로 예약하고, 두 사람이 같은 경로로 이동한다.
병원에서30틱을 마쳐야 가족·국고가 진료비를 나눠 내고 회복한다. 아이가 움직였거나
병원이 만석이거나 보호자가 사라지면 돈·회복 없이 해제한다. 동행은 임금 노동이 아니다.

시정에서 진료 자기부담률과19세 미만 아이당 일일 가구 지원금을 정한다. 가구 지원은
실제 부모 관계와 동거를 확인해 아이당 한 번, 자금이 적은 가구/부모부터 지급한다.
학생에게 임금을 주거나 욕구를 원격 회복시키지 않는다.

## 숨겨 둔 게임 화면은 최신 상태 하나만 받는다 (#143)

탭이 보이지 않는 동안 그 화면으로 주민 전체 배치를 계속 보내지 않는다. 마을 시뮬레이션과
다른 열린 화면은 그대로 진행하며, 탭을 다시 보면 최신 스냅샷 하나로 현재 시각·주민·지도·
정책을 맞춘다. 숨겨진 동안의 말풍선 연출은 뒤늦게 몰아서 만들지 않는다.

## 성인 자녀는 조건을 갖춘 뒤 빈집으로 분가한다 (#51)

같이 사는 실제 부모가 있는 19세 이상 성인 자녀는 학생·아동이 아니고 유급 직업, 준비금,
빈집이 7일 연속 유지되면 분가를 계획한다. 실제 이사는 다음 tick에 같은 조건을 다시 확인한
뒤 id가 가장 앞선 빈집으로 간다. 그 사이 돈·직업·가족·집 조건이 바뀌면 이동하지 않고 실패
사유를 남긴다. 학생은 소득 있는 근로자로 간주하지 않으며 분가 안정 기간도 쌓이지 않는다.
분가는 주민·현금·주택을 새로 만들지 않는다. 가구별 주민·관계·현금·예상 소득·고용·침대는
스냅샷에 기록되어, 같은 집과 같은 가구를 구분해 관찰할 수 있다.

## 집의 위치와 이용 수요가 임대료가 된다 (#93)

학교·병원·치안·소방·공원·도서관·시장에 가깝고 실제 이용이 많은 곳 주변의 지가와 임대료가
높다. 공가도 호가가 보인다. 한 집에 여러 가구가 살면 임대료를 가구 수로 나누고, 각 가구는
가진 현금까지만 낸다. 주민 소유 집이면 실제 소유자가 받고 공공 주택이면 국고가 받으므로
돈이 허공에서 생기거나 사라지지 않는다. 소유자가 자기 집에 살면 자기 자신에게 임대료를
내지 않는다. 소득 대비 부담이나 체납이 3일 이어진 가구는 더 싸고 충분히 넓은 빈집을 찾고,
다음 tick에도 조건이 맞을 때만 전원이 함께 이사한다. 학생을 근로소득자로 계산하지 않는다.

## §22.24 부재중 연대기 — 리포트가 집계가 아니라 이야기가 된다 (이슈 #90)

가상 플레이어의 실측 지적(§22.11 지적 5): **부재중 리포트 74줄 중 61줄이 심별 식사
횟수 목록이었고, highlights 50칸 중 48칸을 `lonely`가 먹었다.** ×48 배속에서는 부재중
1시간이 기본40일 달력의3년이다(당시120일 달력에서는1년) — 그 사이의 사망·사별·결혼·선거·화재를 식사 횟수 나열로
받는 것과 시간순 이야기로 받는 것은 같은 데이터의 다른 배열이다. Dwarf Fortress
레전드 모드가 참조점이다: 시뮬레이션에 아무 영향을 주지 않고, 이미 쌓인 사건 로그를
**이야기의 형태로 재배열**만 한다.

- **읽기 전용 투영**이다 (`server/chronicle.js`, §22.8 view.js와 같은 계층).
  커밋된 이벤트만 읽고(§17.8 — 미커밋 노출 금지는 /api/report의 커밋 틱 클램프가
  그대로 지킨다), 시뮬 상태·rngSim·리플레이에 손대지 않는다 — 결정성 리스크 0.
- **선별은 결정적 우선순위 테이블**: 사망 > 사별 > 자립 > 결혼 > 선거 > 화재·구조 >
  승격 > 전직 > 정책 > 연애·이별 > 챙김·나눔 > 이주·생애 전환 > 완공·축제 > … 순.
  이벤트 스키마에 없는 것을 지어내지 않는다 — 로그의 사실만 문장 틀에 끼운다.
- **종류별 상한(8) + 총 예산(48)**: 한 종류가 자리를 다 먹지 않는다(lonely 48/50의
  재발 방지). 상한을 넘치면 최근 것을 남기고, 예산을 넘치면 낮은 우선순위부터
  오래된 것을 줄인다(1차 패스는 종류당 1건은 남긴다). 출력은 (tick, ordinal) 오름차순.
- **수치를 숨기지 않는다 (§0.1)**: 접힌 사건은 "(지면상 접힌 사건: 병치레 +1523 ·
  나눔 +128)"로, 고빈도 지표는 하단 "◇ 집계" 한 줄로 남는다 — 행동·식사·근무·말다툼·
  외로움·굶주림·주민 잔액 총계. lonely 수치를 깎은 게 아니라 **자리를 정해준 것**이다.
- 심별 식사/근무/잔액 목록은 전송에서 뺐다(§22.8 — 화면이 쓰는 필드만). 대신 인물
  한 줄이 남는다: 최대 증감자("벌이가 가장 좋았던 사람: 김우진 +13,331원").
- 죽은 사람은 `world.sims`에 없어 클라이언트가 이름을 못 찾는다 — 서버가 died
  payload의 이름을 커서 구간이 아니라 **보존 창(30일, 프루닝과 같은 기준)에서**
  `deadNames`로 모아 보낸다 (지난 리포트 구간에서 죽은 부모를 이번 구간의 자립
  문장이 참조해도 안전 — Codex 교차 리뷰 2회 반영). 창의 하한을 프루닝 커토프에
  맞춰 프루닝이 언제 돌았든 리포트가 같고, 장기 실행 중 무한 누적도 없다.
  창 밖 사망은 '심N'으로 접는다.
- 한국어 조사는 §22.12 헬퍼로 처리하고, '으로/로'의 **종성 ㄹ 예외**('마을로')를
  아는 `ro()`를 같은 가족으로 추가했다. 전직 문장이 전 직업을 언급하므로 OCC_KO를
  sim/traits.js의 16종 전체로 확장했다.

## 겨울을 앞두고 식재료를 비축한다 (#92)

기본40일 달력을10일씩 나누어 봄·여름·가을·겨울이 바뀐다. 기존 저장의 달력 설정은
이관으로 강제로 바꾸지 않는다. 겨울10일 전부터 주민은 긴급
한 끼 비용을 남길 수 있을 때 시장에서 미리 식재료를 산다. 목표는6개이며 이미 찬 공간에
이중 구매하지 않고 실제 받은 수량만 결제한다. 품절이면 물건도 지출도 생기지 않는다.
학생도 생활 장보기는 하지만 공급 운반·상업 재배 노동은 최종 졸업 전까지 하지 않는다.

겨울에는 수확·낚시 수입이 절반(정수 내림)이고 야외 활동의 체력 비용이 늘어난다. 실내
휴식에는 추위 비용이 없다. `seasons.*`로 규칙을 조정하며 자동 계절 전환은 난수를 쓰지 않는다.
압박과 대응 효과는 동일한 자연 성장 저장의 비축 on/off 비교로 확인한다.

## 생활이 안정되면 문화 서비스를 찾는다 (#91)

모든 주민은 정착민으로 시작한다. 네 기본 욕구가 모두4000 이상인 실제 tick을 누적하고,
배고픔·체력이1000 미만이면 누적을 한 tick씩 잃는다.7200tick 실적이 쌓이면 시민이 된다.
부자·고소득 직업이라는 이유만으로 승급하지 않으며 학위나 학생 신분도 바꾸지 않는다.
시민이 기본 결핍에 연속720tick 머물면 정착민으로 돌아간다. 문화 결핍만으로 강등하지 않는다.

시민의 문화 욕구는 시간에 따라 줄고 도서관/영화관 방문 후보가 된다. 실제 이동 후40tick
서비스를 받아야100원을 시설에 내고 문화 욕구·재미가 회복된다. 마지막 한 끼 현금은 남긴다.
갈 시설이 없는 경우와 돈이 없는 경우는 구분해 기존 일상 산업 수요 원장에 연결한다.
학생도 문화생활은 하지만 이 기능으로 근무 자격을 얻지 않는다. `needsTiers.*`가 수치 규칙이다.

## 마을 소속을 저장한다 (#32 R-C 선행)

기존 해솔은 `village:0` 하나로 기록한다. 주민의 소속은 거주하는 집을 따르고 직장·장보기
방문 때문에 바뀌지 않는다. 결혼·분가·임대 이사·신축 이주가 실제로 집을 바꿀 때 소속도
함께 갱신한다. 출생·이민·플레이어 생성과 신축 시설은 해당 집/공터의 소속을 전달한다.
기존 마을의 국고 권위는 world에 남고 새 마을은 독립 잔액0으로 출발한다. 지속 부족 청원·
승인·유상 건설·가족의 실제 도보 정착으로 새 마을이 생기며 인구나 국고를 복제하지 않는다.
선거·정책·평판·관측 재정 이력은 마을별로 처리한다. 성장/산업 수요·교통은 후속이다.

## 마을별 계획 중심지 (#32)

계획 중심지(`plan_center`)는 선택한 마을의 국고로 투자한다. 마을을 생략한 과거 입력은
기존 마을 대상으로 유지된다. 자동 투자는 해당 마을 주민의 외곽 주거 수요·소속 공터를
확인하며, 학생 또는 미완료 학위 과정의 시장은 투자 업무를 하지 않는다. 중심지의 건설
위치 유도 효과도 같은 마을 공터에만 적용된다. 성장/산업 수요의 지역 분리는 아직
진행 중이다(PLAN의 #32 마을별 계획 중심지, `zone.plannedCenterCost/centerRadius/centerMinResidents`).

## 마을별 도로 투자 (#32)

실제 반복 우회 보행은 주민 소속 마을별 청원이 된다. 지역 시장은 자기 주민의 반복 횟수와
자기 국고로 계획/완공을 결정하며 일일 투자 가드도 독립적이다. 이미 승인된 도로는 이후
주민 이동으로 다른 마을에 떠넘기지 않는다. 두 마을이 같은 구간을 요청해도 실제 지도에서
이미 짧아진 경로는 청원만 정리하고 재지출하지 않는다. 시설 보호와 통행 지도는 공유된다.
누적 마모 보수는 가장 가까운 창건 중심지(맨해튼 거리, 동률은 마을 ID 오름차순)가 담당한다.
이는 수요 추가가 아니라 기존 보행 마모의 관리 구역 구분이다. 학생/미완료 학위 시장은
도로 투자 업무를 하지 않으며 비용은 지역 국고와 공유 경계 유출에 한 번씩 기록된다.
세이브 v70 이하의 기존 도로 청원/계획은 원래 마을 책임으로 유지하고 과거 마모를 복제하지 않는다.

## 마을별 승급·외부 이민 (#32)

외부 이민은 기존 주기/평판 웨이브 식을 마을별로 적용하며 해당 마을의 빈 침대가 있어야 한다.
다중 마을에서는 기존 지도 입구(2,23)에서 집 문까지 도달할 수 있어야 한다. 불가능하면
주민 생성·난수 추출·초기 자금 유입 없이 건너뛴다. 이민자는 집으로 순간이동하지 않고 기존
입구에서 시작하며 ID/난수/관계 배열/경계 유입은 공유 월드에서만 갱신한다. 이웃 기억과 입국 시
공공직 정원은 거주 마을 주민 기준이다. 승급은 지역 인구로 결정하고 평판·축하 기억·등급
건설 허용도 지역에만 반영한다. v71 이하 저장의 기존 마을 등급은 유지하고 새 정부는0부터
실제 관측으로 승급한다. 건설 수요/산업·학교 배분, 마을 간 이주·방문과 확장 UI는 후속이다.

## 새 마을의 주변 공터 (#32)

실제 도착으로 마을이 생긴 뒤, 유료 중심지 입력 직후와 일일 평가 때, 기존 미배정 공터 중
창건 중심 또는 자기 정부의 유료 중심 반경 안에 있고 창건 중심에서 걸어갈 수 있는
건축 가능한 부지를 소속시킨다. 유료 입력 직후 배정하므로 다음 자동 계획 전에 사용자가
일반 유료 건설 지시를 내릴 수 있다. 원래 마을 중심 반경은 보존하며,
이미 소속이 명시된 땅·사용 중인 땅·공사/구획 주문·승인/공사 중 개척 부지와 다른 정부의
계획 중심지 반경은 가져가지 않는다. 여러 마을이 가능하면 거리·마을 ID 순으로 정하고,
한 번 명시된 소속은 여기서 바꾸지 않는다. 빈 마을은 새 땅을 배정받지 않는다. 새 지형·공터·
인구·자금 생성은 없으며 소속 변경은 이벤트와 재접속 스냅샷에 반영된다.

## 지역별 건설과 계획 중심지의 부지

다중 마을의 주택·직장·학교·산업 수요와 건설 슬롯은 각 지역의 주민, 시설, 실제 근무
자격, 관측 기록과 국고를 쓴다. 남의 침대나 산업 증거를 빌리지 않으며 지역 내 대기
공사 용량을 중복 주문하지 않는다. 한 지역의 가득 찬 공사 슬롯이 다른 지역 주문을
막지 않는다. 공사 완료 전에는 실제 시설 용량이 늘어나지 않는다.

계획 중심지 인근의 빈 부지가 도로와 겹치면 일일 계획 때 바로 옆 잔디로 부지만
옮길 수 있다. 최대8칸이며 도로·지형은 그대로 둔다. 사용/주문/개척 예약된 부지는
옮기지 않고 다른 부지와 시설을 침범하지 않는다. 중심지 지정은 수요 없는 건물을
강제로 생성하지 않는다.

신축 대학은12×10으로 고등학교8×6보다 크다. 교육 슬롯 수는4로 유지한다. 넓은
대학 부지가 없다는 이유로 주택 건설까지 막지는 않는다. 기존 완공 대학은 자동으로
철거하거나 확장하지 않는다. 이전 규격으로 시작한 대학 공사는 주변 여유가 없으면
8×6을 유지해 도로를 침범하지 않는다.

건설 창의 등급과 국고 표시는 선택한 부지 소속 마을을 따른다. 계획 중심지 요청에도
그 마을 ID를 보내며 기본 마을 국고로 대신 청구하지 않는다. 사용/공사/주문/개척 예약
부지는 선택 목록에서 제외한다. 등급 미달·소속 정부 누락·미구현 역 건설은 제출하지
않는다. 건설 주문의 최종 권한·비용·부지 검사는 서버가 다시 수행한다.

## 마을 밖 시설 방문 관측 (#32)

실제로 출발하고 다른 마을 시설의 목적 자원 좌표에 도착한 이동을 기존 교통 원장의
municipalVisits에 목적별로 집계한다. 출발 당시 거주 마을과 도착 시설의 소속이 모두
관측되어야 하며 도중에 거주 소속이나 시설 소속이 바뀐 이동은 방문으로 세지 않는다.
이사/개척, 집으로 돌아가기, 취소, 출발을 관측하지 못한 이전 저장의 이동도 제외한다.
날짜를 넘긴 여행은 도착한 날에 전체 보행 시간을 기록한다. 거주 소속·주거·돈·경로·
행동 선택·난수는 변경하지 않는다. 이는 국경 통과 횟수나 고유 방문자 수가 아니라
다른 마을 서비스 시설에 도착한 횟수다. 같은 마을 밖 시설을 다시 방문하면 다시 센다.
기존14일 교통 기록과 스냅샷으로 전달하며 과거 방문을 소급 생성하지 않는다. 필드가
없다고 과거에 방문이 전혀 없었다는 뜻은 아니다. 일반 방문의 중력 기반 목적지 선택은
아직 미완료이며, 아래 임대료 이주·분가 목적지 선택과 구분한다.

## 다른 마을로의 임대료 이주 (#32)

기존 임대료 압박이 다른 마을의 더 싼 빈집을 선택하면, 주소를 즉시 바꾸지 않는다.
배우자·자녀를 포함한 연결 가족 전체가 목적지에 들어갈 수 있어야 집을 예약한다.
가족은 기존 집에 모여 이동하며, 모두 실제 목적지 문에 도착한 뒤에만 homeId와 마을
소속을 함께 바꾼다. 부모에게 자동차가 있어도 가족 이동 속도는 한 칸/tick이다.
허기·에너지가 부족하면 먼저 회복하고, 이동 중에도 저장·재개할 수 있다.

가족 구성·기존 거주지 변경, 목적지 점유/화재/예약 손실, 길 차단은 이주를 취소한다.
취소는 예약만 풀며 주민을 순간이동시키거나 돈을 만들지 않는다. 한 가족이 동시에
여러 목적지를 예약하지 못한다. 출발 마을 시장이 이주하면 도착 확정 때 그 직을 비우고
다음 정규 선거를 기다린다. 도착 마을의 시장직을 자동으로 얻지는 않는다.
같은 마을 안의 이사는 기존 즉시 도착 처리다. 미졸업 학생은 예상 근로소득 계산에서도 제외한다.

여러 마을이 있으면 임대료 때문에 이미 이사하기로 한 가구의 목적지를 조건부로 고른다.
도달 가능하고 가족을 수용하며 현재보다 싼 빈집 중 마을별 최저 임대료 집 하나를
대표로 삼는다. 실제 마을 인구/그 집까지의 보행 경로 길이에 비례해 선택하므로 같은
마을의 빈집 수를 중복 가산하지 않는다. 후보 하나면 추첨하지 않으며, 모두 인구0이면
경제적 최저가 선택으로 돌아간다. 후보·인구·거리·가중치·추첨값은 이주 의도에 남는다.
단일 마을은 기존 목적지 선택과 난수 소비를 유지한다. 이 규칙은 이주 원인을 새로
만들거나 이동 빈도를 강제하지 않으며, 일반 시설 방문의 목적지 선택과도 별개다.

## 다른 마을에서의 독립 (#32)

부모와 함께 사는 성인 자녀의 기존 안정 소득·예비금·지속일 조건을 통과한 독립 의도가
다른 마을 집을 고르면 집을 예약하고 실제로 이동한다. 부모 가구 전체가 아니라 해당
성인·배우자·함께 사는 미성년 자녀를 연결해 출발 가구를 계산한다. 부모와 형제는 남는다.
전원이 목적지 문에 도착해야 새 주소·마을·독립 가구 ID를 함께 확정한다. 가족이 들어갈
수 없거나 도달할 수 없는 다른 마을 빈집은 건너뛴다. 마을 안의 주택 선호는 기존 ID 순이다.
여러 마을에서는 분가 자격과 빈집/가족 수용량 검사를 통과한 뒤 마을별 관측 인구와
실제 보행 경로 거리로 목적지를 선택한다. 마을 안에서는 기존 집 ID 순서를 유지하고,
후보 집이 많다고 마을 가중치가 늘어나지 않는다. 여러 양수 가중치 목적지가 있을 때만
추첨1회이며 선택 근거는 의도와 집결 이벤트에 저장한다. 집결/여행 중 저장 후에도
다시 추첨하지 않는다. 단일 마을 선택과 RNG 소비는 기존대로다. 임대료 이주의
최저 임대료 선호와 달리 분가는 ID 선호를 명시하며 실제 임대료 관측은 보존한다.

모임 중 학생 신분·소득 불안정·예비금 부족, 가족 구성 변경, 목적지 점유/화재·경로 차단은
예약을 풀고 취소한다. 이미 이동한 좌표를 되돌리거나 돈·주민을 만들지 않는다. 다른
이주와 같은 가족을 중복 예약하지 않으며 이동 중 저장·재개를 지원한다. 같은 마을의
기존 독립 동작은 유지한다. 다른 마을에 나뉘어 사는 배우자는 아래 혼인 합가 경로를 쓴다.

## 마을 간 혼인 합가 (#32)

결혼식과 혼인 관계는 기존 시점에 성립한다. 다른 마을로 합가할 때 주소만 즉시 바꾸지
않고 다음 틱의 내구 이주 의도를 만든다. 부부와 함께 사는 미성년 자손을 계산하되,
목적지에 이미 사는 가족은 남아 있고 실제 출발자만 모여 이동한다. 모든 출발자가 문에
도착하면 주소·마을을 확정하고 자녀도 혼인 가구 ID에 포함한다. 부모·동거인은 흡수하지
않는다. 시장도 실제로 다른 마을로 떠나는 사람의 원래 직만 도착 때 비운다.

우선 기존 배우자 집을 검사하고, 별거 부부의 재시도에서는 가족이 들어갈 수 있는 다른
주택도 찾는다. 기존 거주 인원과 동반 자녀를 합산해 수용량을 확인한다. 집이나 길이
없으면 기존 별거 재시도로 남겨 두며, 인구·침대·결혼 확률을 조작하지 않는다. 목적지
추첨은 추가하지 않는다. 가족/배우자 거주지/기존 입주자·예약·길이 바뀌면 취소한다.

예약된 집의 빈 자리는 도착자를 위해 비워 두되, 현재 거주자가 이미 쓰는 침대는 건설
수요에서 계속 센다. 예약 때문에 기존 주민이 갑자기 집이 없는 것으로 계산되지 않는다.
이주 통계는 rent_move/separate/marriage_move를 구분한다. 단일 마을 혼인 동작은 유지하되
예약된 배우자 집에 다른 합가가 즉시 끼어드는 것은 막는다.

## 신축 주택으로의 마을 간 이주 (#32)

일반 주택 완공 후 과밀 주택을 과밀도 내림차순·주택 ID 오름차순으로 검사하고, 주민은
ID 내림차순으로 검사한다. 목적지가 다른 마을이면 해당 주민 한 명만 보내지 않고
연결 가족 전체의 수용량·경로·기존 이주 약속을 확인한다. 들어갈 수 없는 가족 때문에
다른 가능한 가구의 입주까지 막지는 않는다. 새집은 완공 시점에 예약해 같은 틱의 이민이나
다음 건물 완공이 중복 배정하지 못하게 하고, 다음 틱의 기존 모임·보행 경로로 이동한다.

전원 도착 후 주소·마을과 새집 기억을 확정하며 가구 ID는 유지한다. 이동 준비 중 원래
집의 과밀이 해소되면 취소한다. 가족/목적지/경로 변경 역시 기존 이주 취소 규칙을 따른다.
가족이 들어갈 집이나 길이 없으면 construction_relocation_deferred에 사유를 남긴다.
이 construction_move도 원인별 이주 통계에 포함한다. 개척용 예약 주택은 일반 배정에서
제외한다. 지역 내 신축 배정은 기존 완공 틱의 최고 ID 주민 즉시 이사 계약을 유지한다.

## 개척 이후 관측 명령

`/api/industry`의 `employment`는 지자체별 근무 가능 무직자, 직종별 시설 수용량과
거주 근로자 수, 채용 조건을 만족하는 빈자리, 착공/주문 수를 분리한 읽기 전용 계측이다.
학생·미완료 학위·19세 미만·은퇴 연령 무직자는 구직 인원에서 제외한다. 기존 사무실의

사무직도 기존 기반 부문의 외부 소득 모델을 유지하며 실제 빈자리에서 재취업한다.
서비스 채용 뒤·임금 체불 퇴직 전에 지자체 ID순으로 하루 최대1명을 적성/ID순 후보와
기존 dayHash 확률로 채용한다. 학생·학위·연령, 해당 마을의 접근 가능한 자리와 거주
사무직 수, 전역 전체 용량을 모두 확인한다. 사건 중인 건물은 제외한다. 돈은 실제
근무를 완료해야 기존 임금/세금/경계 유입 원장으로 지급한다. 직장 배정이 없는 현재
모델에서 거주 직업 수는 실제 자리 점유·통근을 측정한 값이 아니다. 기존 서비스 채용은 전역
판정이므로 지자체 수치는 지역 계획용 근사(scope)이며 채용 보장이 아니다. 구직 인원은
여러 직종 후보에 중복 등장할 수 있으므로 직종별 eligibleApplicants를 합산하지 않는다.
소비 시설 부족 원장에는 이 숫자를 더하지 않는다. 별도 officeConstruction 증거의
부족분(기존 사무직+다른 업종의 빈자리로 흡수 못 한 구직자−기존 자리−착공/주문 자리)을
지역 계획이 사용한다. 서비스 전역 정원에서 실제 직업 보유자를 뺀 잔여 자리와 각 지역의
수요가 뒷받침된 자리를 함께 제한한다. 직종순·적성/ID순으로 자리와 구직자를 전역에서
한 번만 대응시키며, 채용 확률0인 후보를 가상의 채용 여력으로 차감하지 않는다. 사무실의
일시 폐쇄는 신축 수요로 추가하지 않는다. 신축 사무실당4자리를 착공/주문 시 반영한다.
자동 사무실 건설도 해당 지자체 예산(기본3000)을 기존 구역 비용으로 지불하고 외부 유출로
기록한다. 기본 노동량8000과 학교/주거 우선순위는 유지한다. 완공 전 자리는 채용에
사용할 수 없다. employment_construction_planned 이벤트에 판단 근거와 비용을 남긴다.
사건 중인 사무실은 물리적 capacity에 남지만 recruitmentCapacity에서 제외한다.
산업 시설 부족 분류도 사건 중인 시설만 있으면 unavailable이며 no_facility가 아니다.

`node bench/founding-construction.js 32 --settle --family --traffic --retain-native-plots`는
기존 가족의 실제 건설·이동·정착 후30일 동안 마을별 시설 성장과 서비스 도착을 관측한다.
`--resume-traffic`를 더하면 관측 중간에 저장·재개한다. 원래 시드의 공터를 보존하되
초기 과밀/지형/승인은 통제한 fixture이므로 자연 포화나 자연 개척 완료 증거로 쓰지 않는다.
공터 보존 옵션 없이 실행한 결과는 공터0개라는 조건을 함께 읽어야 한다. 이 명령은
메모리에서 새 세계를 실행하며 플레이 서버나 저장 파일을 변경하지 않는다.

## 외부 사건 입력 (#32 R-D, schema75/logic93)

`POST /api/input`의 `world_event`는 기존 내구 입력 큐를 사용한다. 예시 payload는
`{"effect":"disease","percent":200,"durationTicks":1440}`이다. effect는 disease 또는
immigration만 허용하며 percent는0~300 정수, durationTicks는1~43200 정수다.
추가 필드와 임의 로직 경로는 거부한다. 100은 원래 효과,0은 일시 억제다.
같은 종류의 후속 입력은 기존 사건을 교체하며 다른 종류와 곱셈 중첩하지 않는다.
적용 tick부터 적용 tick+durationTicks 직전까지 유효하다. 만료는 해당 tick의
입력 처리 전에 한 번 발생하고, 같은 tick의 후속 사건은 sequence 순으로 적용한다.

disease는 기존 일일 발병 위험(기아·비·피로 보너스 포함)과 접촉 전염 확률에 적용하며
정수 내림 후1000퍼밀로 제한한다. 추가 난수 소비 없이 기존 면역·회복·사건 제시를
유지한다. immigration은 기존 평판/도시등급 웨이브를 백분율로 조정해 내림한다.
기존 이민 주기·빈 침대·도달 가능성·직업 생성·유입 자금 회계를 그대로 통과한다.
이는 입국 신청량 조정이며 인구 목표값 설정이나 현금 직접 지급 입력이 아니다.
현재 모든 마을에 적용되며 마을별 타깃, 대화 가중치·기분 충격은 아직 제공하지 않는다.

활성 목록 worldEvents는 세이브·접속 스냅샷·tickBatch에 포함된다. 기존 세이브는
빈 목록으로 마이그레이션하며 기존 기본 로직 값은 덮어쓰지 않는다.
world_event_started/expired가 적용·교체·만료를 기록한다. 전용 UI는 아직 없다.

후속 logic94는 `topic_` 접두 효과를 제공한다: couple_news, family_talk, food,
gossip, memory_share, politics, weather, work_gripe, sweet_talk, club_talk.
실제 문맥에서 가능한 주제만 백분율 가중 조정하며 최근 주제 반복 방지와 초대 우선은
그대로다. 모든 후보가 사라지면 기존 weather 발화로 폴백하므로 weather0은 침묵 명령이
아니다. 활성 사건이 후보를 모두 제거한 경우에는 기존 빈 후보 분기의 무추첨이 적용된다.
검증 중인 후속 변경이며 기분 충격과 전용 UI는 남아 있다.

후속 logic95 기분 사건은 `{effect:"mood",delta:-2000,durationTicks:1440}` 형식이다.
delta는-3000~3000 정수이며 percent와 혼용할 수 없다. 적용 시 현재 기분과 대기 중인
기상 기분에 충격을 주고, 활성 기간에는 기존 생활 기반 회복 기준점에 delta를 더한다.
동일 활성 채널 교체는 주민별 실제 반영량을 제외한 뒤 새 delta를 적용한다. 상한/하한으로
잘린 미적용분까지 차감하지 않으며, 동일 delta 연장은 충격을 반복하지 않는다.
실제 반영량은 사건의 applied에 저장되고 회고/기상 때 갱신된다. 기분은-10000~10000으로
제한한다. 만료 시 과거 기분을 복원하지 않고 평소의 생활 기반 회복으로 돌아간다.
이는 검증 중인 구현이며 실제 행동 영향·전체 회귀·리뷰는 아직 완료되지 않았다.

### 혼인 합가 목적지 (logic96)

다중 마을의 기존 물리적 혼인 합가 경로는 가족 전원이 들어갈 수 있고 도달 가능한
주거만 대상으로 조건부 중력 선택을 한다. 각 마을의 ID 순 첫 후보 주거 하나를 대표로
사용하며 가중치는 현재 거주 인구/실제 도보 경로 길이다(거리 최소1). 출발 기준은 기존
혼인 경로에서 이주하는 높은 ID 배우자의 현재 집이다. 배우자와 자녀는 서로 다른 집에서
출발할 수 있으므로 이는 가족 전체 이동 거리의 최적화가 아니라 일관된 선택 기준이다.
결혼 당일에는 기존 낮은 ID 배우자 집만, 별거 중 재시도에서는 다른 주거도 후보가 된다.
이미 같은 마을에서 가능한 기존 합가와 단일 마을의 동작은 바꾸지 않는다.

다른 가구가 예약/신청한 집, 사고 시설, 부족한 침대, 단절된 경로는 선택에서 제외한다.
양의 가중치를 가진 마을이 둘 이상일 때만 회고의 혼인 처리 위치에서 rngSim을1회 소비한다.
후보·거리·인구·드로우는 내구 의도의 migrationChoice로 보존하며 진행 중인 이동을 다시
추첨하지 않는다. 선택만으로 주소를 바꾸지 않고 기존 모임→이동→전원 도착을 거친다.
일반 방문의 목적지 중력 선택 및 공항·정치·외교·전쟁은 이 변경의 완료 범위가 아니다.

### 일반 방문 목적지 (logic98, 검증 중)

기존 후보 효용과 동점 규칙으로 행동을 먼저 선택한다. 비위급 일반 방문(eat, socialize,
play, drink, binge_eat, exercise, read, shop, fish, stroll, volunteer, board_game,
stock_food, visit_culture)에만 같은 행동의 가능한 마을별 목적지를 고른다. 각 마을에서는
기존 점수/동점 순의 첫 도달 가능한 자원이 대표가 된다. 자원 개수가 인구 가중치를 중복
증폭하지 않는다. 가중치는 현재 마을 인구/현재 위치에서 자원까지의 도보 경로 길이이며
거리는 최소1이다. 이웃 마을 시설도 원래 후보 자격·돈·예약·재고 검사를 통과해야 한다.

위급 욕구, 파티 약속, 근무·학교·돌봄·화재·공사·배송·집의 고정 목적지는 바꾸지 않는다.
단일 마을이나 같은 행동 후보가 한 마을에만 있으면 추가 탐색/난수가 없다. 도달 가능한
마을 중 양의 가중치가 둘 이상일 때 tick의 idle 결정 단계에서 rngSim을1회 소비한다.
0인구 마을들만 있으면 기존 점수로 선택한다. 방문 선택은 행동을 바꾸거나 거주지를 바꾸지
않으며, 선택한 경로를 startAction에 재사용하고 기존 철도 수단 선택/실제 이동을 거친다.
action_started.reason.visitChoice에 좌표·거리·인구·선택 근거를 기록한다. 실제 도착만
기존 municipalVisits 통계에 집계된다. 세이브 상태 필드 추가는 없어 schema75를 유지한다.
마을 인구/시설 조회표는 idle 결정 단계에서 한 번 관측하며 다음 tick까지 캐시하지 않는다.
선택된 경로는 재탐색하지 않고 즉시 기존 이동 시작에 전달한다.

## 세계 사건 입력 화면

상단의 ‘세계 사건’ 버튼에서 효과, 값, 게임 내 기간(1~30일)을 선택한다. 모든 마을에
적용되며 같은 종류의 기존 사건을 교체한다는 설명을 제출 전에 표시한다.
저장 완료는 실제 적용 완료와 구분한다. 적용 목록과 남은 게임 시간은 서버 스냅샷과
tickBatch만으로 갱신한다. 응답 유실/서버 오류로 저장 여부가 불확실하면 입력값을 잠그고
동일 clientInputId로 재확인하므로 사건이 중복 생성되지 않는다. Escape 또는 닫기로 나간다.
실제 Chrome/임시DB/별도포트에서 저장 후 응답 유실→재시도→활성 표시→재접속 검증을
수행했다. 이 검증은 사용자 플레이 서버나 세이브를 변경하지 않는다.
