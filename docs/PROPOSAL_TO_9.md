# 제안: 평가 평균 5.5 → 9.0 (Opus 구현용 로드맵) — v2, Codex 1차 리뷰 반영

**성격**: 제안서. 구현하지 않는다. 각 항목은 *파일·함수 / 완료 기준(숫자) / 테스트 / 예상 점수*로 적는다.

**v2에서 바뀐 것** (Codex 1차 판정 NO-GO의 조건 4개를 전부 반영):
1. Tier 0에서 시뮬 변경(구 T0-4b)을 **제거** — 원시 이벤트로 확인하니 오진이었다(§2 T0-4).
2. "게임으로서 계속"을 직접 겨냥하는 **핵심 루프 T1-0**을 추가하고 게이트로 삼았다.
3. T2-3 최근 발화 캐시를 **결정성을 깨지 않는 방식**으로 재설계했다.
4. 점수를 **8항목 평균으로 재계산**했다. 산술만으로는 8.6이고, 9.0의 나머지는 T1-0 재검증에 달렸다고 명시한다.

## 0. 전제

- "9점" = `docs/REVIEW_RUBRIC.md` 8항목 평균 9/10 (★4.5급). 3차(5인) 실측 **5.5/10, ★2.5, 게임으로서 계속 0/5**.

  순서는 창 수리 → 게임화 → 설명 → 마감. 창이 거짓말하는 동안 넣는 기능은 아무도 못 본다(§22.22가 그랬다).
- 계약: §0.1(지표 조작 금지·행동 추가), 결정성(`state[t]=simulate(state[t-1],inputs[t])`; **클라의 모든 선택은
  이벤트에 이미 실린 값만으로 결정**), `sim/` 변경은 Codex 합의 + 해시·리플레이 테스트, 새 건물 = 5장 에셋.

## 2. Tier 0: 거짓말 멈추기 — **시뮬 로직 변경 없음**

**T0-1 상단바 라이브 갱신** — `client/main.js` tickBatch 분기가 `world.sims`·`world.treasury`를 갱신하고 `updateStats()`를
호출하지 않는다(snapshot 분기에서만 호출). 3인 목격, confirmed.
- 완료: 국고가 바뀐 tickBatch 처리 직후 `#stats`가 갱신. 테스트: tickBatch 주입 후 `#stats` 검사.

**T0-2 온보딩 성씨** — `sim/tick.js:577-579`는 `p.surname` 없으면 `surnameFor()`로 부여; 폼(`client/index.html:179`)에
성 칸·안내가 없고 payload(`client/main.js:1868-1872`)가 surname을 안 보낸다. 4인 목격.
제안: 폼에 **성 칸(선택)** + "비우면 마을 성씨 분포에서 뽑습니다". 성은 **서버 입력으로만 결정**되어 스냅샷에 저장
(클라 임의 생성 금지 — 결정성). `player_created` 피드(1726행)는 `simName`과 같은 표기.
- 완료: 입력 10건 + 공란 케이스에서 모든 표시 경로(피드·패널·이름표)가 `성+이름` 일관, 미등록 토큰 0건.

**T0-3 상단바 레이아웃** — `client/index.html:15-17` `#clock`이 `position:absolute`로 흐름에서 빠져 📣 버튼을 덮는다.
in-flow로 옮기고 2단(지표/도구)·1000px 줄바꿈 규칙.
- 완료: 1000/1400/1920 폭에서 `elementFromPoint(버튼 중앙)` === 그 버튼. 스냅샷 3장.

**T0-4 피드 신호/잡음 분리 (클라 전용)** — 전원 불만 1순위 "공사 돕기 시작/완료 즉시 쌍 도배".
**시뮬 원인이 아니다**: 테스터 DB 3개(Day 0·2·11) construct 575쌍의 시작→완료 tick 차이는 **최소 60·중앙 60·같은 틱 0건**
(`sim/logic.js` `construct: {duration: 60}`과 일치). 배속에서 한 배치에 두 이벤트가 실려 붙어 보이고, 60틱=1시간이라
매시 같은 분에 반복된다. **표시 착시다 — 시뮬을 건드리면 오진 수정이다.**
제안: 이벤트 중요도 계층. *사건*(결혼·출생·사망·굶주림·파산·선거·완공·정책·모임)은 개별 노출, *루틴*(work·sleep·eat·
construct의 started/completed)은 시간 단위 롤업("01시: 여도윤 외 4명이 공사를 도움") + "루틴 보기" 토글.
**원본 이벤트 스트림은 보존**(표시만 집계).
- 완료: 분모를 원본 이벤트 수로 고정, 토글 끔 상태에서 Day 0~10 피드 줄 중 루틴 ≤ 30%. 토글 켬은 100% 노출.

**T0-5 내부 표기 우리말화** — `OCC_KO` 5종뿐·폴백 없음(3인 `(undefined)`), `treasury_short`·`plot_used`·`[근무✗시간 아님]`.

enum 집합 == 클라 표기 집합.
- 완료: 등록된 모든 이벤트 타입·enum의 표시 커버리지 100%(테스트), 피드에 `undefined`·스네이크케이스 0건.

**T0-6 적자를 말하게** — sim은 `treasury_debt`·`wage_shortfall`·`insolvent`를 emit(§22.23)하는데 클라가 렌더 안 함(§22.37 부류).

## 3. Tier 1: 게임이 되게 하기

**T1-0 핵심 루프 (신설, 게이트)** — "게임으로서 계속 0/5"를 직접 겨냥한다. 루프: **행동(정책·건설·심 지시) → 세계 변화
(이벤트) → 결과 카드 → 다음 목표**. 성공/실패 조건을 명시한다:
- 성공: 목표 트리(T1-4) 노드 달성 → 카드 + 다음 노드 제시.
- 실패: 국고가 3일 연속 음수·굶주림 N건 → "위기" 카드 + 회복 행동 제안(세율·복지·건설 취소).
- 완료: 신규 세계에서 30분 플레이 시 루프 1회전(행동→카드→다음 목표) ≥ 3회. **게이트: 재검증에서 "게임으로서 계속" ≥ 3/5.**

**T1-1 첫 3줄 + 첫 목표 카드** — "당신은 시장 / 국고 −10,459원, 공무원 3명 무급 / 🏛️에서 세율을". 첫 정책 후 소멸.
- 완료: 신규 세계 첫 접속 1회, `localStorage` 재표시 억제.

**T1-2 한 명 따라가기** — G-0 통과 후 심 클릭 판정 확정. 팔로우 모드: 카메라 추적 + 타임라인(기억·관계 변화·판단 사유).
서사파가 "관계를 반영한 대화"를 최고 장점으로 꼽았다 — 게임의 축으로.
- 완료: 팔로우 5분간 사건이 시간순 타임라인에 ≥ 5건.

**T1-3 레버의 인과** — 정책 변경당 **정확히 1장**의 결과 카드(3일 뒤): 변경 전/후 값 + 3일 구간 실측(세수·굶주림·지지도).
sim 변경 없음(기존 이벤트 집계).

**T1-4 목표 트리** — `city_promoted`·§18 티어·§19.12 기차역이 이미 있다. 모든 노드에 현재값·목표값·상태·도달 행동 표시.
승급 로직은 손대지 않는다.

**Tier 1 재계산**: 재미 5.0→8.0(T1-0 +1.5, T1-2 +0.8, T1-3 +0.7) · 이해도 5.8→8.3 · 조작UI 7.0→8.0 · 그럴듯함 6.9→7.4
→ **평균 7.5**. 게이트 ★4.0 + **게임으로서 계속 ≥ 3/5**.

## 4. Tier 2: 세계가 설명되게

**T2-1 판단 사유 노출** — README 약속(§22.11 #4). `action_started.payload.reason.chain`이 이미 있다(위 표본 참조) —
패널에 "왜 이걸 골랐나"를 문장으로. 모든 항목에 현재값·비교값 표시.
- 완료: 패널에 사유 ≥ 3줄, 미등록 사유 토큰 0건.

**T2-2 무급 공무원의 행동 (sim, Codex 합의)** — Day 0 적자를 §0.1대로 *이야기*로 만든다. 구체 전이:
`wage_shortfall` 누적 N일(파라미터) → 결정적으로 다음 중 하나 emit: `protest`(시청 앞 집결, 기존 petition 부류 재사용) /
`job_changed`(민간 전직, §21.3 경로 재사용) / `side_job`(신규 행동). 초기 국고는 늘리지 않는다.
- 완료: 무급 상태 1440틱 이내 결정적 행동 ≥ 1회, 그 행동과 결과 이벤트가 기록되고 해시·리플레이 테스트 통과.

**T2-3 대화 반복 억제 — 결정성 보존 재설계** — 1차 안(클라 로컬 최근 발화 캐시)은 **폐기**: 접속 시점·리싱크·배치 경계에
따라 캐시 내용이 달라져 같은 이벤트가 다른 문장이 된다(Codex 지적, 맞다).
대안 A(클라, 무상태): 선택 인덱스를 `tick`만이 아니라 `(tick, 화자id, 청자id)` 해시로 — 같은 쌍의 연속 대화가 서로 다른
줄을 고르도록 *상관을 끊는다*. 완전 억제는 아니다.
대안 B(sim, Codex 합의): 페이로드에 **쌍별 대화 카운터** `pairSeq`를 싣고 클라가 그것으로 고른다 — 상태가 서버에 있어
어디서 접속해도 같다. 완전 억제.
- 완료: 새 접속·리싱크·재생성에서 같은 이벤트의 문자열 해시 동일(결정성) + 같은 쌍의 N=6시간 내 동일 문장 재사용률
  측정치를 보고(억제 목표는 B에서 0건).

**T2-4 모임 0명 참석 (sim 조사 → 구체화)** — 공지 전 소문 3회, 당일 0명, 공지자 본인도 공사 돕기. 가설: 초대 이행(§22.6)이
construct의 고정 급함(`logic.js:85` `NEED_MAX - deficit`)에 밀린다.
- 완료: 초대→수락→참석 이벤트 수치가 실제 심 상태와 일치하고, 공지자 본인 참석률 100%, 수락자 참석률 ≥ 70%(파라미터).

**Tier 2 재계산**: 그럴듯함 7.4→8.6(T2-1 +0.4, T2-2 +0.5, T2-4 +0.3) · 재미 8.0→8.4(T2-3 +0.2, T2-4 +0.2) → **평균 7.8**.

## 6. 9.0까지의 남은 0.4 — 산술이 보장하지 않는 부분

위 합산은 8.6이다. 9.0은 두 곳에서만 나온다: (1) **T1-0 루프가 실제로 "게임으로서 계속"을 3/5 이상 만들면** 재미가

8→9다. 둘 다 재검증 실측으로만 확인된다. **9.0을 약속하지 않는다 — 8.6은 산술, 나머지는 게이트 통과가 조건이다.**

| Tier 1 | 평균 ≥ 7.5, ★4.0, **게임으로서 계속 ≥ 3/5** | 같은 5인 |

상위 버그는 계속 반박 검증(confirmed만 고친다). `sim/` 변경(T2-2·T2-3B·T2-4)은 각각 Codex 합의 + 해시·리플레이 테스트.

## 8. 하지 말 것

- 점수를 위해 지표를 만지지 않는다(§0.1). 적자·굶주림은 숨기지 않고 설명한다.
- Tier 0 전에 Tier 1·2를 하지 않는다. **Tier 0에 `sim/` 변경을 넣지 않는다.**
- 클라의 선택을 클라 로컬 상태에 의존시키지 않는다(T2-3 1차 안이 그랬다).
- 원본 이벤트 스트림을 삭제하지 않는다(롤업은 표시만).

## 9. Opus 구현 지시 형식

한 항목 = 한 작업: (1) 파일·함수 (2) 완료 기준 — 숫자 (3) 회귀 테스트 — 고치기 전 상태에서 **실제로 실패**하는지 확인
(4) 예상 점수 (5) **파괴적 검증 전 커밋**(§22.37·§22.39 사고).
